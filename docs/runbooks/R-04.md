# R-04 · 1С не запускается / тормозит

**Severity:** P2 (P1 если это вся компания)
**Tier:** all
**Time budget:** 90 мин до восстановления
**Requires:** доступ к серверу 1С, к MS SQL / PostgreSQL, к клиентским машинам (через RDP/AnyDesk)

---

## 1. Триггер

- Клиент пишет «1С не работает».
- Alert из Prometheus: `pg_stat_activity` активных соединений > threshold.
- Alert: `1c_server_process` systemctl / службы Windows отсутствуют.
- Alert: disk usage на БД-сервере > 90%.

---

## 2. Диагностика

### 2.1. Уточнить у клиента

- «Не запускается» vs «тормозит» vs «зависает при конкретном действии»?
- Затрагивает всех или одного?
- С какого момента (час? день?)
- Что изменилось (обновление платформы, конфигурации, сервера)?

### 2.2. На сервере 1С

```
# Windows
Get-Service '1C Enterprise Server'
Get-Process '*1cv8*'
Get-EventLog System -Newest 50

# Linux
systemctl status srv1cv8-*
ps aux | grep ragent
tail -100 /var/log/1C/*
```

### 2.3. На сервере БД

```sql
-- PostgreSQL
SELECT count(*), state FROM pg_stat_activity GROUP BY state;
SELECT pid, now() - pg_stat_activity.query_start AS duration, query, state
FROM pg_stat_activity WHERE (now() - pg_stat_activity.query_start) > interval '1 minute';
```

```
-- MS SQL
SELECT COUNT(*) FROM sys.dm_exec_sessions WHERE is_user_process = 1;
EXEC sp_who2 active;
```

## 3. Действия

### 3.1. Не запускается — сервис упал

- [ ] Попробовать restart: `systemctl restart srv1cv8-*` / `Restart-Service '1C Enterprise Server'`.
- [ ] Если не стартует — посмотреть logs на причину (лицензия, permissions, файл конфига).
- [ ] Если упала лицензия (HASP) — проверить, что HASP-ключ на месте, драйверы актуальны.
- [ ] Если credentials БД изменились — обновить в SrvrHA.cfg.

### 3.2. Тормозит — БД перегружена

- [ ] Убить долгие запросы (если это не критические операции клиента):
  ```
  SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE (now() - query_start) > interval '10 minutes';
  ```
- [ ] VACUUM (PostgreSQL) или статистика (MS SQL).
- [ ] Проверить, есть ли «долгий фоновый» (регламентированные отчёты).

### 3.3. Тормозит — мало RAM / CPU

- [ ] Временно увеличить VM ресурсы (cloud можно за 5 мин).
- [ ] Убрать неиспользуемые сеансы.
- [ ] Если это регулярное — плановый upgrade (обсудить с клиентом как ADDON).

### 3.4. Проблема у 1 пользователя

- [ ] Очистить кэш платформы: `C:\Users\<user>\AppData\Local\1C\1Cv82\<cache>`.
- [ ] Проверить версию клиента (должна совпадать с сервером).
- [ ] Проверить сеть (ping, traceroute до сервера).

## 4. Откат

- Если мы ребутили сервер → данные обычно не теряются (транзакционная СУБД).
- Если меняли конфиг — вернуть из git.

## 5. Проверка

- [ ] 1С открывается.
- [ ] Клиент подтвердил, что всё работает.
- [ ] Мониторинг 1С-сервиса green.
- [ ] `pg_stat_activity` в норме (active < 20).
