# MSPShield XMPP Invite Portal

Приглашения новых пользователей в XMPP (Prosody) через домен `invite.msp-claude.online`.

## Как работает

- **Админка**: `/admin?token=<XMPP_INVITE_ADMIN_TOKEN>` — создание, список, копирование ссылок, удаление.
- **Создание приглашения**: выдаётся только ссылка (заметка + срок); аккаунт заранее НЕ создаётся.
- **Гость** открывает `/i/<token>`: ссылки на приложения (Conversations / Monal / Gajim),
  сам выбирает логин и пароль → «Создать аккаунт» (аккаунт создаётся в Prosody,
  приглашение становится использованным, данные входа показываются на экране).
- **Удаление аккаунта**: в этом сетапе Prosody не умеет `deluser` онлайн, поэтому портал
  стирает файл стора и коротко перезапускает контейнер (`−аккаунт` в админке).

## Деплой (VM)

- `/opt/xmpp-invite/`: `app.py`, `venv/`, `data/invites.db`, `.env` (токен админа, 600).
- systemd unit: `xmpp-invite.service` → `127.0.0.1:8895`.
- Caddy: `invite.msp-claude.online` → `127.0.0.1:8895` (раньше смотрел на старый Jami-портал).

## Проверка

```bash
curl -s http://127.0.0.1:8895/health           # {"ok": true}
curl -s -H "X-Admin-Token: <токен>" http://127.0.0.1:8895/admin/invites
```

## Личный кабинет и админ-контроль пользователей (догонка 2)

- **Личный кабинет**: `/login` (JID + пароль, проверка через SASL) → `/u`: свои данные,
  **создание приглашений** для коллег, смена пароля. Сессия — cookie на 30 дней.
- **Админка пользователей**: в `/admin` раздел «Пользователи» — все аккаунты Prosody
  со временем обновления и статусом приглашения; кнопки «новый пароль» (сгенерировать
  и показать) и «удалить» (короткий рестарт Prosody).
- Приглашения, созданные из кабинета, помечаются автором (`created_by`).

Ещё грабли (проверено):
- В Python-строке `stat -c '%Y %n'` знаки `%` нужно экранировать (`%%Y %%n`),
  иначе `%`-форматирование падает с `unsupported format character`.

## Догонка 3: инвайт = просто ссылка, логин выбирает гость (06.10.2026)

- Приглашение больше НЕ создаёт пользователя заранее: выдаётся только ссылка (+ заметка, срок).
- На странице `/i/<token>` гость сам выбирает логин и пароль (автогенерация),
  жмёт «Создать аккаунт» → аккаунт сразу заводится в Prosody, приглашение становится
  использованным, данные показываются на экране.
- QR-код убран из приглашения и кабинета: в XMPP-клиентах нет автонастройки аккаунта по QR
  (нет такого стандарта у клиентов) — без пользы только путал.
- Кавычки внутри JS-строк, собираемых в Python f-строках, требуют ДВОЙНОГО
  экранирования (`\\"`): одиночный бэкслеш «съедает» Python, и JS ломается
  (симптом: `Uncaught SyntaxError: Unexpected identifier 'muted'`).
  После правок проверять: извлечь `<script>`-блоки страниц и `node --check`.

## Грабли (проверено)

- `prosodyctl register` для СУЩЕСТВУЮЩЕГО пользователя молча перезаписывает пароль —
  поэтому портал сначала проверяет наличие файла аккаунта и отвечает «занят».
- Имена файлов аккаунтов экранируются: `invite-qa` → `invite%2dqa.dat` (дефис = %2d,
  точка = %2e); удаление считает имя по тому же правилу и проверяет результат.
- `prosodyctl deluser` в этом сетапе не работает онлайн (нет admin shell) — удаление =
  стереть файл стора + короткий рестарт контейнера

## Догонка 4: подсказки клиентам — «У меня уже есть аккаунт» (06.10.2026)

- Симптом от коллеги: «аккаунт по приглашению не входит, пишет что не работает регистрация».
  Диагноз: аккаунт на сервере полностью рабочий (проверен полный вход: SASL + bind + roster, сертификат ок),
  но клиенты при выборе пункта «Зарегистрироваться/Создать аккаунт» получают от сервера отказ
  (регистрация в приложении выключена — и это правильно). Нужно выбирать **«У меня уже есть аккаунт»**.
- На странице приглашения усилены подсказки: жирное «Добавить аккаунт → У меня уже есть аккаунт»,
  «не выбирайте Регистрация», отдельный абзац «Пишет „регистрация запрещена“? — выбирайте „У меня уже есть аккаунт“»,
  и в форме создания — «Логин создаётся здесь; регистрация в приложении не нужна».
- `/welcome/<token>` → 307-редирект на `/i/<token>` (совместимость со старыми ссылками Jami-эпохи;
  визит на `/welcome/...` = 404 и путаница — теперь безболезненно).
