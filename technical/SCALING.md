# Масштабирование MSPShield

> Как расти от 1 клиента до 50. Что меняется в архитектуре, команде и процессах.

## Фазы масштабирования

```
┌──────────────┬──────────────┬──────────────┬───────────────┐
│  Phase 0     │  Phase 1     │  Phase 2     │  Phase 3      │
│  SOLO        │  TEAM-2      │  TEAM-5      │  SCALE-UP     │
├──────────────┼──────────────┼──────────────┼───────────────┤
│ 1-3 клиента  │ 4-10         │ 11-25        │ 26-50+        │
│ 1 человек    │ 2 (senior+jr)│ 5 (1+2+2)    │ 8-12 (+sales) │
│ 75-200k MRR  │ 200-500k     │ 500k-1.5M    │ 1.5M+         │
│ Всё вручную  │ Отчёты auto  │ Billing auto │ Self-service  │
└──────────────┴──────────────┴──────────────┴───────────────┘
```

## Phase 0 → Phase 1 (важный переход)

Признаки, что пора нанимать junior:
- Отказ от 2-го клиента в месяц из-за нехватки времени
- Переработки > 50 часов/месяц регулярно
- MRR ≥ 150 000 ₽ (можно позволить junior 80-100k зарплату)
- У вас 5+ клиентов — каждый weekly-check по 2 часа = уже 40 ч/мес

### Что готовим к приходу junior
- [ ] Разделение ролей L1/L2/L3 (см. [`../docs/training/README.md`](../docs/training/README.md))
- [ ] Все плейбуки написаны и актуальны
- [ ] Bitwarden с ролевыми shared коллекциями (Bronze / Silver / Gold)
- [ ] Notion-шаблон клиентской страницы
- [ ] Регламент онбординга junior ([`../docs/training/week_01.md`](../docs/training/week_01.md))

## Инфраструктурное масштабирование (исполнитель)

### Вариант А: Один общий Bastion + multi-tenant Monitoring VM

```
 Bastion VM              Monitoring VM (общий)
 WireGuard  ────────→    Prometheus scrapes all clients
                         Grafana folder-per-client
```

**Пределы:** до 15–20 клиентов. После этого Prometheus начинает тормозить scrape.

**Как усилить:**
- Prometheus Remote Write → **Mimir / VictoriaMetrics** для долгого хранения
- Разделить Prometheus на shards по client groups
- Grafana tenants (через Grafana Enterprise или каждому — свой namespace в folders)

### Вариант Б: Dedicated stack на клиента (начиная с Gold)

```
Client A: own Monitoring VM + Loki + Wazuh (если Gold)
Client B: own Monitoring VM
...
Управление единое: через Terraform + Ansible + Git
```

**Когда переходить:** если у клиента >50 серверов или требования compliance запрещают multi-tenant.

Плюсы: изоляция данных, compliance-friendly, масштабируется без ограничений.
Минусы: выше OpEx (3k ₽/клиент/мес на инфра), сложнее ops.

## Архитектурное масштабирование по фазам

### Phase 1 — Team of 2 (4–10 клиентов)

**Изменения в стеке:**
- Общий Monitoring VM c увеличенным CPU/RAM (4 vCPU / 8 GB → 8/16)
- Loki вводим для всех, даже на Bronze (для рассортиовки логов по клиентам)
- Переход на **Terraform** — разворачивание клиентской инфры в коде
- Backup-мониторинг отдельным экземпляром prometheus (дедупликация — наш меж-региональный)

**Инструменты роста:**
- **Reliable backup verifier** (скрипт monthly-restore уже не руками — через GH Actions cron)
- **amoCRM** для sales pipeline
- **Банковское API** для автоматических счетов/актов (Тинькофф для бизнеса, Точка)

### Phase 2 — Team of 5 (11–25 клиентов)

**Инфра:**
- Кластер Prometheus (Thanos / Mimir) с долгосрочным хранением в S3
- Разделение на **общий SIEM** (Wazuh cluster) для всех Gold-клиентов
- **Grafana Cloud** или своё enterprise (видимость всеx клиентских dashboards в одной консоли)
- **Ansible AWX** / **Semaphore** — визуализация запусков playbooks
- **Vault HashiCorp** вместо Bitwarden (секреты в коде и playbook'ах)

**Процессы:**
- **On-call rotations** — 24/7 смены для Gold-клиентов
- **Dedicated Sales/BDM** (Product Marketing) — владелец компании не масштабируется
- **Client Success Manager** — отвечает за retention + upsell

**Финансы:**
- Автоматическое billing (выставление счетов через Эвотор-онлайн или Мои самозанятые)
- ЭДО через Диадок / СБИС обязательно

### Phase 3 — Scale-up (26–50+ клиентов)

**Инфра:**
- **Multi-region** Yandex Cloud (Москва + Петербург failover)
- **Собственный SaaS-портал** — клиент видит свой dashboard без Grafana-учётки
- **API-first**: всё через код, zero-touch provisioning клиента
- **SOC (Security Operations Center)** — круглосуточная очередь L1 для Gold

**Команда:**
- CTO (архитектура)
- 2 senior (Silver/Gold)
- 3 L2 (Silver)
- 3 L1 (Bronze + L1 SIEM)
- 1 sales manager
- 1 customer success
- 1 accountant (outsource)

**Продукт:**
- Публичный self-service: клиент ввёл домен → получил Bronze trial на 14 дней
- ADDON-маркетплейс внутри портала (клиент сам заказывает)
- Партнёрские программы с 1С-франчайзи, хостерами, интеграторами

## Масштабирование сервисов клиента

Что делать, когда у существующего клиента РАСТЁТ инфраструктура.

### Клиент добавил 5 новых серверов
- [ ] Добавить в `clients/<slug>.yml` секцию `services.*`
- [ ] Запустить `onboard_client.sh` — он перегенерирует prometheus targets
- [ ] Ansible-playbook разворачивает агенты автоматически
- [ ] Проверить что новые серверы видны в Grafana
- [ ] Если клиент на Silver/Gold — добавить в Puppet manifest
- [ ] Доп. стоимость — если серверов больше, чем в тарифе заложено (обычно Bronze = до 5, Silver = до 15, Gold = до 40). Сверх — ADDON «+сервер» 2-3k₽ на каждый.

### Клиент открыл второй филиал
- [ ] Развернуть второй WireGuard client cfg
- [ ] Настроить маршруты между сетями (если клиенты сам хочет cross-region connectivity)
- [ ] Добавить новый location в Yandex Cloud (если нужен региональный Monitor)
- [ ] Проектная работа: оценить отдельно (от 80k)

### Клиент хочет HA для 1С
- [ ] Это проект, не routine. См. [`ADDONS.md`](./ADDONS.md) → «HA 1С»
- [ ] Оценка отдельно, 150-300k₽
- [ ] Приводим senior + 1С-франчайзи клиента

### Клиент хочет DR (disaster recovery)
- [ ] Gold-тариф (обязательно) + ADDON «DR-сайт»
- [ ] Разворачивание Yandex Cloud в другом регионе (ru-central1-b или c)
- [ ] Asynchronous репликация (BD — через логическую репликацию, файлы — restic + rsync mirror)
- [ ] RTO ≤ 4 часа, RPO ≤ 24 часа
- [ ] Стоимость: +15k ₽/мес (инфра) + 100k одноразово (настройка)

## Проблемы роста и как их решать

| Проблема | Симптомы | Решение |
|---|---|---|
| Alert fatigue | Инженеры игнорируют алерты | Калибровка rules, классификация severity, дедуп в Alertmanager |
| Single Grafana для всех клиентов | Панели смешиваются | Folders + organizations / отдельные tenants |
| Prometheus retention мал | Архив за год не хранится | Thanos / Mimir, long-term в S3 |
| Ручные манифесты AD/GPO | Ошибки, расхождения | Puppet с rspec-тестами |
| Команда рвётся | Выгорание после 12-го клиента | Нанимать junior заранее, не когда уже горит |
| Клиенты «всё хотят в цене Bronze» | Убытки по часам на клиента | Чёткий scope в договоре, ADDON-прайс доступен |

## Финансовый roadmap

```
Мес 1-3:   0-2 клиента · инвестиция 150-200k₽ · Cash-flow: -150k
Мес 4-6:   3-5 клиентов Bronze · MRR 75-125k · Break-even
Мес 7-12:  7-10 клиентов mix · MRR 250-450k · Первая прибыль
Год 2:     12-20 клиентов + team-2 · MRR 500k-1M · Масштаб
Год 3:     25-40 клиентов + team-5 · MRR 1-2.5M · Scale-up
```

## Правила владельца при масштабировании

1. **Не нанимай инженера, пока не можешь платить 3 мес вперёд.**
2. **Нанимай sales/BDM раньше, чем 3-го инженера.**
3. **Автоматизируй то, что делаешь > 3 раз в месяц.**
4. **Документируй всё. Если ты попадёшь в больницу, бизнес должен работать.**
5. **Стандартизируй клиентов.** 10 разных стёков — это 10 разных проектов. 50 похожих — это продукт.
