# Kaiten для небольшой команды

[Продажи](../chapters/18-sales.md) · [Клиентский процесс](../chapters/14-client.md) · [Рабочая настройка](../../docs/KAITEN_SETUP.md)

Kaiten помогает видеть работу людей: кто отвечает, что ожидается и когда следующий шаг. Mongo хранит исходные заявки, договор — обязательства, Git — версии кода, vault — секреты. Карточка не заменяет ни одну из этих систем.

Начать с доски продаж и доски исполнения с различимыми типами «подключение», «инцидент», «изменение». Отдельное пространство/права клиента проверять фактически; фильтр метки не является защитой доступа. Возможности бесплатного тарифа/автоматизаций сверять с действующим аккаунтом, не строить обязательство на неподтверждённой функции.

В карточке: клиент/объект, ответственный, тип/приоритет, срок или окно, ожидаемый результат, риск, ссылка на разрешение и подтверждение. Секреты не вставляются. Персональные контактные сведения — только по утверждённой схеме обработки; обещание «в CRM вообще нет ПДн» не соответствует доставке lead.

Ограничение незавершённой работы (WIP) не даёт начинать всё сразу. Для пилота сначала проверить одну основную задачу на человека и порядок срочной работы; корректировать по возрасту очереди и доступным часам. Сам факт отдельной срочной дорожки не создаёт резервного инженера.

Безопасная автоматизация назначает метку/напоминание или шаблон. Закрытие инцидента требует проверки человека; автоматическая смена стадии без критерия портит аналитику. Каждое правило сначала проверяется на учебных карточках.

Практика: провести учебную компанию от обращения до передачи, затем отдельное изменение и инцидент. Для каждой карточки назвать вход, владельца и результат. Измерить время ожидания отдельно от активной работы. [Официальные уроки и границы видеоссылок](../VIDEO_GUIDE.md#облако-и-рабочие-инструменты).
