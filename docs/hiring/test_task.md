# Тестовое задание · Junior MSP Engineer

**Лимит:** 3 часа. Оценивается безопасное мышление, а не объём кода. Использовать только тестовые значения.

## Часть 1 — диагностический script

Написать `disk_report.sh` с `--threshold`, exit codes 0/1/2 и русской шапкой:

- назначение и место запуска;
- входы и побочные эффекты;
- проверка успеха;
- откат или объяснение, почему не требуется.

Обязательны `set -euo pipefail`, безопасное quoting и отсутствие дополнительных пакетов.

## Часть 2 — backup/restore

Написать идемпотентный Ansible playbook установки restic и короткий runbook:

1. backup тестового каталога;
2. удаление одного файла;
3. restore в отдельный clean-каталог;
4. измерение RPO/RTO;
5. evidence без credentials.

Задание, которое только создаёт snapshot и не проверяет restore, не засчитывается.

## Часть 3 — troubleshooting

Разобрать сценарий: VM имеет status RUNNING, ICMP закрыт, HTTPS недоступен, последний backup старше 24 часов. На русском описать:

- безопасный порядок диагностики;
- как отличить cloud stop от Caddy/SG/network failure;
- какие данные запросить у клиента;
- rollback и коммуникацию;
- какие alert/runbook улучшить.

Запрещено предлагать `StrictHostKeyChecking=no`, отключение TLS/auth или изменение production без change record.

## Оценка

| Критерий | Вес |
|---|---:|
| безопасность, rollback и stop conditions | 30% |
| работающий код и идемпотентность | 25% |
| реальный restore evidence | 20% |
| диагностика и коммуникация | 15% |
| русская документация и логичные commits | 10% |

Автоматический отказ: реальные секреты/ПДн, destructive command без предупреждения, подделанное evidence.
