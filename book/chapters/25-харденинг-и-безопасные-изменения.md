# 25. Харденинг и безопасные изменения

> **Учебная ситуация.** Нужно закрыть публичный SSH, не потеряв управление VM.

## Главное

Defense in depth: cloud SG и ufw независимы. Закрытие только одного слоя оставляет зависимость от другого.

Сначала проверяется AWG tunnel, routing и SSH к private VPN address. Затем удаляется public rule.

Break-glass заранее описывает возврат временного public rule, repair и повторное закрытие. Это не постоянный bypass.

## Слова, которые встретятся дальше

### attack surface

Все доступные интерфейсы и возможности, через которые система может быть атакована: ports, accounts, APIs, packages и supply chain.

### break-glass

Заранее подготовленный аварийный путь с ограниченным использованием, audit и обязательным возвратом к защищённому состоянию.

### least privilege

Identity получает только actions/resources/time, необходимые задаче. Удобство не является доказательством необходимости admin role.

## Как это работает

Закрытие 22 выполняется как change с двумя каналами доступа. Сначала VPN connection и SSH по private address, затем ufw, затем SG, затем внешний negative test. Break-glass правило открывается временно, ограничивается адресом по возможности и удаляется после ремонта.

## Пример

```bash
sudo ufw delete allow 22/tcp
sudo ufw status numbered
nc -vz PUBLIC_IP 22
ssh ubuntu@10.9.0.1
```

### Что здесь происходит

- `sudo ufw delete allow 22/tcp` — `sudo` запускает следующую программу с повышенной effective identity; shell уже обработал кавычки, glob и redirection.
- `sudo ufw status numbered` — `sudo` запускает следующую программу с повышенной effective identity; shell уже обработал кавычки, glob и redirection.
- `nc -vz PUBLIC_IP 22` — `nc -vz` проверяет установление TCP без application protocol; успех не означает корректный HTTP/TLS.
- `ssh ubuntu@10.9.0.1` — Разделите строку на программу/оператор, options и operands; затем по документации установите side effect и exit semantics.

## Практикум

1. Поднимите test tunnel.
2. Закройте 22 на host и SG.
3. С другого канала выполните break-glass и снова закройте.

## Если что-то не работает

| Наблюдение | Что это означает | Следующая проверка |
|---|---|---|
| Закрыли до проверки VPN | использовать cloud console/temporary SG по runbook. |
| VPN работает, DNS нет | SSH по private IP отделяет проблемы. |
