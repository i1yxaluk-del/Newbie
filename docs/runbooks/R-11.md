# R-11 · DR drill (ежеквартально)

**Severity:** P4 (плановые работы)
**Tier:** all
**Time budget:** 4 часа на 1 клиента
**Requires:** доступ ко всем бэкапам, scratch-space, `dr_drill.sh`

---

## 1. Триггер

- Квартальный cron: первая неделя квартала.
- Ad-hoc: после инцидента с backup'ами (см. R-03).
- Ad-hoc: перед подписанием нового Gold-клиента (их SLA требует подтверждения RPO/RTO).

---

## 2. Подготовка (за 1 неделю)

- [ ] Выбрать клиента для drill (ротация, чтобы за год все прошли).
- [ ] Предупредить клиента (информативно, не запрашиваем подтверждение).
- [ ] Подготовить scratch-environment (отдельная VM / namespace), чтобы не помешать production.
- [ ] Убедиться, что `technical/0_Common/scripts/dr_drill.sh` работоспособен.

---

## 3. Действия

### 3.1. Smoke DR (30 мин)

```bash
./technical/0_Common/scripts/dr_drill.sh acme
```

- Restic check прошёл.
- Latest snapshot есть.
- Single-file restore успешен.

Если всё ок — переходим к full restore (если tier Silver/Gold).

### 3.2. Full DR (для Silver/Gold; 2-3 часа)

- [ ] Развернуть новую VM по шаблону (terraform-module tenant_scratch).
- [ ] Восстановить **всё содержимое** последнего snapshot в новую VM.
- [ ] Запустить ключевые сервисы клиента на этой VM (1С, AD, etc).
- [ ] Верифицировать, что сервисы работают (health-check).
- [ ] Зафиксировать **фактические RTO/RPO** (от команды до работающего сервиса).

### 3.3. Application-level checks (для Gold)

- [ ] Базу данных — consistency check.
- [ ] AD — `dcdiag` на восстановленном DC (не в production-домене!).
- [ ] 1С — запуск demo-транзакции.
- [ ] Сравнить checksum критичных файлов с production.

---

## 4. Откат

- Уничтожить scratch-VM после drill (`terraform destroy` в scratch-workspace).
- Убедиться, что не осталось тестовых пользователей / креденшалов в AD production (если вдруг были).

---

## 5. Проверка / acceptance

- [ ] Actual RTO ≤ declared SLA (Bronze 4h, Silver 2h, Gold 1h).
- [ ] Actual RPO ≤ declared SLA (Bronze 24h, Silver 12h, Gold 4h).
- [ ] Все критические сервисы подняты.
- [ ] Нет data corruption.

Если actual > SLA — это **finding**, требует action items.

---

## 6. Коммуникация

- Клиенту (Bronze/Silver): не докладываем в моменте, включаем в monthly report («провели DR-drill, результаты: RTO X, RPO Y»).
- Клиенту (Gold): отдельный 1-pager с результатами, отправить в течение 3 дней после drill.
- Внутренне: post-drill retro в Kaiten.

---

## 7. Post-actions

- [ ] Post-drill retro: что занимает больше всего времени в restore, что можно ускорить.
- [ ] Обновить inventory типов тестов (может, добавить новый scenario).
- [ ] Обновить SLA-документ, если обнаружены расхождения с реальностью.
- [ ] Следующий drill для следующего клиента запланирован.
