# Linux, процессы и сеть

Linux — операционная система виртуальной машины. Она запускает программы, хранит файлы и управляет пользователями. Администратор сначала наблюдает, затем меняет.

**Процесс** — запущенная программа. **Служба** — процесс, которым управляет `systemd`. **Порт** — номер сетевой точки входа. **Журнал** — последовательность сообщений программы.

```bash
pwd
ls -la
systemctl status docker
ss -lntp
```

`pwd` показывает текущую папку. `ls -la` показывает файлы, включая скрытые. `systemctl status` читает состояние службы. `ss -lntp` показывает программы, которые слушают TCP-порты. Эти команды предназначены для наблюдения.

Журнал Docker за текущую загрузку:

```bash
journalctl -u docker -b --no-pager
```

Флаг `-u` выбирает службу, `-b` — текущую загрузку системы. Не копируйте в тикет токены и пароли из журнала.

## Как запрос попадает на сервер

DNS возвращает IP-адрес. Браузер создаёт TCP-соединение. При HTTPS стороны договариваются о шифровании TLS. Caddy принимает запрос на 443-м порту и передаёт его приложению на `127.0.0.1:8001`.

`127.0.0.1` — адрес самой машины. Он не доступен напрямую из интернета. Это и есть нужная схема: наружу смотрит Caddy, а серверная часть остаётся внутри.

Проверяйте путь слоями: сначала DNS, затем доступность порта, сертификат, ответ Caddy и только после этого приложение. `ping` не проверяет HTTPS и может быть запрещён при полностью рабочем сайте.

## Практика

На учебной VM найдите процесс SSH, порт 22 и его журнал. Затем запустите простой локальный веб-сервер и убедитесь, что привязка к `127.0.0.1` не открывает его наружу. Нарисуйте разницу между облачной группой безопасности, `ufw` и слушающей программой.
