# 8. Git как история решений

> **Учебная ситуация.** После обновления библиотеки нужно понять, какая правка вызвала регрессию и как её отменить.

Предыдущая глава: [глава 7](./07-http-tls-и-reverse-proxy.md).

## Модель, которую нужно построить

Commit — снимок дерева плюс родители и сообщение; branch — перемещаемая ссылка. Git хранит историю объектов, а не последовательность «файловых патчей».

Index позволяет выбрать содержимое следующего commit. `git add -p` отделяет логические изменения.

Revert добавляет обратный commit и сохраняет общую историю; reset переписывает ссылку и опасен для опубликованной ветки.

## Термины в рабочем смысле

### commit

Неизменяемый Git-объект со снимком дерева, metadata и parent links. Branch лишь указывает на один commit.

### index

Подготовленное содержимое следующего commit. Оно может отличаться и от working tree, и от HEAD.

### evidence

Минимальный проверяемый артефакт: timestamp, exit code, hash, запрос/ответ, metric или подписанный документ. Скриншот зелёной панели без target и времени — слабое evidence.

## Что происходит внутри

`git diff` без флагов сравнивает working tree с index; `git diff --cached` — index с HEAD. Review должен видеть оба. Pin версии библиотеки превращает build из «последняя доступная» в проверяемый input; обновление pin требует теста и отдельного commit.

## Разобранный пример

```bash
git switch -c docs/lesson
git diff
git add -p
git commit -m "docs: explain MAX session persistence"
git show --stat HEAD
```

### Как читать пример

- `git switch -c docs/lesson` — Git-команда читает или изменяет working tree/index/refs; перед mutation сравните `status` и `diff`.
- `git diff` — Git-команда читает или изменяет working tree/index/refs; перед mutation сравните `status` и `diff`.
- `git add -p` — Git-команда читает или изменяет working tree/index/refs; перед mutation сравните `status` и `diff`.
- `git commit -m "docs: explain MAX session persistence"` — Git-команда читает или изменяет working tree/index/refs; перед mutation сравните `status` и `diff`.
- `git show --stat HEAD` — Git-команда читает или изменяет working tree/index/refs; перед mutation сравните `status` и `diff`.

## Практикум

1. Сделайте два независимых commits.
2. Создайте конфликт в учебной ветке и разрешите осознанно.
3. Отмените один commit через revert.

## Если результат не совпал с ожиданием

| Наблюдение | Что это означает | Следующая проверка |
|---|---|---|
| CI красный после merge | Это сужает область поиска, но не доказывает единственную причину | сначала читать конкретный check. |
| Большой смешанный diff | Это сужает область поиска, но не доказывает единственную причину | разделить до review. |

## Самостоятельная работа

Решите изменённый вариант исходной ситуации: **После обновления библиотеки нужно понять, какая правка вызвала регрессию и как её отменить.** Измените один существенный параметр — host, port, credential, dataset, пакет или ограничение клиента — и сначала письменно предскажите результат. Затем выполните проверку на безопасном стенде. В отчёте оставьте исходное предположение, фактическое наблюдение, причину расхождения и способ восстановления.
