# 8. Git как история решений

> **Учебная ситуация.** После обновления библиотеки нужно понять, какая правка вызвала регрессию и как её отменить.

## Главное

Commit — снимок дерева плюс родители и сообщение; branch — перемещаемая ссылка. Git хранит историю объектов, а не последовательность «файловых патчей».

Index позволяет выбрать содержимое следующего commit. `git add -p` отделяет логические изменения.

Revert добавляет обратный commit и сохраняет общую историю; reset переписывает ссылку и опасен для опубликованной ветки.

## Слова, которые встретятся дальше

### commit

Неизменяемый Git-объект со снимком дерева, metadata и parent links. Branch лишь указывает на один commit.

### index

Подготовленное содержимое следующего commit. Оно может отличаться и от рабочие файлы, и от HEAD.

### подтверждение

Минимальный проверяемый артефакт: timestamp, exit code, hash, запрос/ответ, metric или подписанный документ. Скриншот зелёной панели без target и времени — слабое подтверждение.

## Как это работает

`git diff` без флагов сравнивает рабочие файлы с index; `git diff --cached` — index с HEAD. Review должен видеть оба. Pin версии библиотеки превращает build из «последняя доступная» в проверяемый input; обновление pin требует теста и отдельного commit.

## Пример

```bash
git switch -c docs/lesson
git diff
git add -p
git commit -m "docs: explain MAX session persistence"
git show --stat HEAD
```

### Что здесь происходит

- `git switch -c docs/lesson` — Git-команда читает или изменяет рабочие файлы/index/refs; перед изменение сравните `status` и `diff`.
- `git diff` — Git-команда читает или изменяет рабочие файлы/index/refs; перед изменение сравните `status` и `diff`.
- `git add -p` — Git-команда читает или изменяет рабочие файлы/index/refs; перед изменение сравните `status` и `diff`.
- `git commit -m "docs: explain MAX session persistence"` — Git-команда читает или изменяет рабочие файлы/index/refs; перед изменение сравните `status` и `diff`.
- `git show --stat HEAD` — Git-команда читает или изменяет рабочие файлы/index/refs; перед изменение сравните `status` и `diff`.

## Практикум

1. Сделайте два независимых commits.
2. Создайте конфликт в учебной ветке и разрешите осознанно.
3. Отмените один commit через revert.

## Если что-то не работает

| Наблюдение | Что это означает | Следующая проверка |
|---|---|---|
| CI красный после merge | сначала читать конкретный check. |
| Большой смешанный diff | разделить до review. |
