## Критические находки (исправлены в этом же PR)

### 🔴 F1. `backend/requirements.txt` содержал `emergentintegrations==0.1.0`

**Симптом:** `pip install -r requirements.txt` падает с
`ERROR: No matching distribution found for emergentintegrations==0.1.0`.

**Причина:** пакет был добавлен платформой Emergent при bootstrap и никогда не
импортировался из кода (`grep -r emergentintegrations backend/src/ → 0`).

**Фикс:** удалена строка. Теперь `pip install -r backend/requirements.txt`
отрабатывает на чистом python 3.12 venv.

### 🔴 F2. `backend/tests/test_mspshield_api.py` — хардкод `/app/frontend/.env`

**Симптом:** `pytest --collect-only` падает с
`FileNotFoundError: '/app/frontend/.env'` на любой машине, где код лежит
не в `/app/`.

**Причина:** платформенный путь Emergent (контейнер с префиксом `/app`).

**Фикс:** `Path(__file__).resolve().parents[2] / "frontend" / ".env"` +
graceful fallback на `http://localhost:8001`. `ADMIN_TOKEN` теперь тоже
берётся из env (`os.environ["ADMIN_TOKEN"]`), а не хардкодится.

### 🟡 F3. `technical/0_Common/docker/docker-compose.yml` — нет `.env.example`

**Симптом:** `docker compose config` падает с
`required variable GRAFANA_ADMIN_USER is missing`.

**Фикс:** создан `technical/0_Common/docker/.env.example` с версиями образов
и плейсхолдерами для `GRAFANA_ADMIN_*`. С ним `docker compose config` проходит.

### 🟡 F4. Три `docker-compose.yml` содержали `version: "3.8"` (deprecated)

**Симптом:** `WARN: the attribute 'version' is obsolete`. Не ошибка, но
compose v2 это игнорирует и логирует warning.

**Фикс:** `sed -i '/^version: /d'` во всех трёх файлах. Warnings пропали.

### 🟡 F5. `frontend/` — остатки платформы Emergent

Найдены и удалены в рамках упрощения лендинга (основная часть этого PR):

- `frontend/package.json` → dep `@emergentbase/visual-edits` (качался с `assets.emergent.sh`)
- `frontend/craco.config.js` → обёртка `withVisualEdits`
- `frontend/public/index.html` → `emergent-main.js` script + `#emergent-badge` элемент

**Риск до фикса:** `yarn install` падал на неаутентифицированном хосте
(`assets.emergent.sh` отдаёт 403 без токена). Теперь `yarn install` работает
на чистой машине.

### 🟢 F6. `verify_all.sh` — 3 shellcheck warning (SC2034, SC2120)

Исправлены минимальными правками (добавлены `# shellcheck disable=` в нужных
местах, убрана неиспользуемая `local expected`).

## Известные, но НЕ исправленные проблемы

### 🔴 K1. Ansible `site.yml` ссылается на 9 несуществующих ролей

`playbooks/site.yml` в `roles:` упоминает:
`baseline, nginx, fastapi_backend, mongo, wireguard_hub, monitoring_agent,
restic_client, base_hardening, ad_health_check`. Ни одной директории
`roles/<name>/` физически нет.

**Следствие:** полная раскатка через `ansible-playbook site.yml` **не
запустится**. Работают только отдельные plays: `backup_install.yml`,
`patch_nondisruptive.yml`, `patch_disruptive.yml` — они используют только
builtin-модули (`apt`, `copy`, `systemd`).

**Почему не фикшу сейчас:** имплементация 9 ролей = недели работы, это
задача спринта 5 Этапа 4 (см. `docs/roadmap/etape_4_sprints.md`).

**Текущая замена:** первичная раскатка landing-стека описана **вручную** в
`docs/deployment/landing_production.md` и `docs/lifecycle/README.md §1.6` —
через `docker compose up`. Это **реально работает сегодня**.

### 🟡 K2. `amtool check-config` не принимает `chat_id: 0`

Alertmanager отбрасывает конфиг, если `chat_id` на telegram_config не задан
(интерпретирует `0` как unset). В нашем `alertmanager.yml` все 3 receiver'а
имеют `chat_id: 0` с комментарием `# override per-tenant через Ansible-шаблон`.

**Следствие:** запустить alertmanager с этим конфигом как есть **нельзя**.
Перед запуском нужно заменить `0` на реальные `chat_id` (один на общий
канал, один на P1-oncall, один на backup) — либо вручную, либо через
Ansible-template в спринте 5.

**Текущая замена:** на уровне 0 мониторинга (UptimeRobot + cron) alertmanager
не нужен, можно поднимать позже.

### 🟡 K3. Prometheus file_sd таргеты отсутствуют

`promtool check config` даёт warning:
```
WARNING: file "targets/node/*.yml" for file_sd in scrape job "node" does not exist
WARNING: file "targets/tenants/*.yml" for file_sd in scrape job "tenant-nodes" does not exist
```

**Следствие:** Prometheus стартует, но scrape job `node`/`tenant-nodes` будут
пустыми (нулевые таргеты). Для monitoring-VM это нормальное стартовое
состояние — таргеты добавляются через Ansible при онбординге клиента.

**Не фикс:** это scaffold-поведение by design. Когда появится первый тенант —
Ansible сгенерирует `targets/tenants/<tenant_id>.yml` и warning исчезнет.

### 🟢 K4. `terraform fmt` — 1 файл

`main.tf` не отформатирован по дефолтному стилю `terraform fmt`.
Исправится командой `terraform fmt -recursive` — не трогаю в этом PR,
чтобы не перемешивать с функциональными правками.

## Заключение

v4.2 — **первая версия репо, которую можно клонировать на свежую машину и
поднять лендинг без лезть в исходники**. До неё `yarn install` / `pip
install` / `pytest collect` / `docker compose config` падали на trivia.

Инфраструктурный код (Ansible/Terraform) остаётся в состоянии **scaffold**:
Terraform готов, Ansible — только патчи и бэкапы, первичная раскатка ручная.
Это ожидаемо для проекта «один человек в свободное время», у которого пока
нет реальных клиентов — ручной деплой одного landing-сервера дешевле, чем
написать и протестировать полноценные Ansible-роли.
