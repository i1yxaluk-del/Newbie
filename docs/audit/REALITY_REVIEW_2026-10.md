# Реализуемость MSPShield в РФ: ревизия 15.10.2026

## Вывод

**Medium:** проект жизнеспособен как небольшой ограниченный B2B-сервис мониторинга, сопровождения и проверки восстановления. Коммерческая жизнеспособность ещё не доказана оплатами, retention и измеренными трудозатратами. Модель «IT-отдел/SOC/24×7 без участия клиента» текущими материалами и составом команды не подтверждается.

**High:** до исправлений активные источники существенно расходились. Публичный SLA обещал P1 за 5–15 минут, фиксированное восстановление, uptime и 24/7, а MSA — рабочие окна и реакцию за 1–4 часа. Gold 85 тыс. ₽ давал расчётную маржу 37,1% при минимуме 50%. Зелёные отдельные валидаторы эти расхождения не обнаруживали.

Проверены канонические коммерческие документы, landing JSON/SEO/активные компоненты, публичные legal HTML, MSA, CI, backend приём/доставка лидов, основной и monitoring Compose, preflight, backup/restore, representative incident runbooks и маршрут обучения. Проверка не является полным пентестом, юридическим заключением или инвентаризацией фактически запущенных VM.

## Исправления и эффект

| Область | Подтверждённая проблема | Изменение |
|---|---|---|
| Экономика | Gold ниже собственного порога маржи; отсутствовал связный бизнес-план | Единая котировка от 120 тыс. ₽, contribution 64 100 ₽/53,4% в исходной модели; sensitivity, CAC/payback, fixed costs, cash reserve и 30/60/90 в `commercial/BUSINESS_PLAN.md` |
| Рынок | Неподтверждённое сравнение с зарплатой администратора | Источники Selectel/ИТ-ГРАД, границы сравнения; гипотеза on-premise/гибридного ICP и оплаченный пилот как проверка спроса |
| Продажи | Gold смешан со стадиями; нет однозначных знаменателей метрик | Gold — атрибут; определения когорт, MRR/CAC/GRR/NRR, поля CRM и capacity gate |
| Маркетинг | Compliance, несколько специалистов, автоматический restore и сроки без evidence | Убраны необоснованные обещания, demo-показатели помечены; отображены лимиты часов; реклама только с проверенным основанием/маркировкой |
| Договор/SLA | Публичные HTML противоречили MSA | Справочные условия вместо параллельной оферты; единые P1–P3, рабочее окно, 5%/15% credits; НДС и раннее уведомление о ПДн-инциденте |
| ПДн | Неизвестный «ИП/ООО», политика ≠ отдельное согласие, ложное «третьим лицам не передаём» | Честно обозначены проекты с незаполненными реквизитами; отдельный consent HTML; запись версии/времени в API; перечень каналов требует утверждения |
| Доставка | MAX/Telegram/SMTP подавляли ошибки; outbox удалял канал как успешный | Явный bool, retry при failure, SMTP в thread, безопасное HTML-экранирование, тесты отказов |
| Outbox | Окно потери до background enqueue, конкурирующая отправка request/poller, падение worker при DB error | Durable marker в lead, reconciliation, один poller, повтор после временной DB error; at-least-once, не exactly-once |
| Deploy | Frontend пропущен в Compose-инструкции; Postbox/direct MX смешаны; вывод SMTP secret | Добавлены build/static, manifest/provider distinction, выбор mail route, config check без печати секретов; непрерываемый production example |
| Backup/DR | Произвольный staging, параллельный backup, позднее обнаружение missing archive | Ограничение staging, flock/umask, error metric; обязательные артефакты проверяются до остановки/`--drop` |
| Restore evidence | Файловый скрипт выдавал время копирования за RTO/RPO сервиса; неверный разбор JSONL | Статус `restore_only`, snapshot age/file duration, прикладной допуск отдельно; исправлен JSONL |
| Junior | Слепое выполнение runbook, blanket DROP, prune при corruption | Стоп-условия, incident lead, сохранение управления/копий; формализован практический экзамен |
| Наблюдаемость | Watcher hardcoded management IP, утечка socket при timeout | Адрес из inventory, Dispose в finally, одинаковый configurable interval |

## Оставшиеся gates — не выдавать за готовность

| Приоритет | Не закрыто | Evidence / владелец |
|---|---|---|
| P0 перед сбором заявок | Реальный оператор, утверждённые policy/consent, РКН/основания, фактическая схема обработчиков | Owner + юрист; заполненные документы и решение до включения формы/API. Один checkbox не легализует неизвестного оператора |
| P0 перед критичным клиентом | Прикладной clean-room restore всего подписанного scope | Engineer/reviewer: данные, зависимости, keys, контрольный запрос, фактические RTO/RPO |
| P0 перед Gold/24×7 | Оплаченная мощность, компетенции, замещение, проверенная эскалация и бюджет | Capacity approval. 168 ч/нед непрерывного поста ≠ три человека в списке |
| P1 | Matrix/MAS/PostgreSQL/media и отдельные сервисы не имеют доказанного покрытия общим migration kit | Отдельные DB-native backups, версии, runbook и restore каждого сервиса; `/opt` archive недостаточен |
| P1 | Одна VM объединяет контроль, vault, мониторинг и доставку | Независимый внешний мониторинг/канал и recovery вне VM; не обещать HA |
| P1 | Старые лиды без `delivery_enqueued` не включаются в автоматический reconciliation | До rollout инвентаризировать старые недоставленные записи; согласованная миграция по ID, без массовой повторной отправки |
| P1 | Удаление ПДн/retention в Mongo/CRM/почте/чатах/backups не доказано | Утверждённый реестр хранения, тест удаления и повтор после restore; предложенные 90 дней ещё не deployed policy |
| P1 | НПД/УСН, лицензии ИБ и рекламы требуют решения для реального исполнителя | Бухгалтер/юрист; НПД 2,4 млн ₽, отсутствие работников, чек; УСН не автоматически без НДС |
| P1 | Старые DOCX в `frontend/public/docs/contracts/` могут отличаться от канонического MSA | Не выдавать за текущий договор; отдельная ревизия/снятие с публикации с владельцем. Каноническая новая сборка — `contracts/build_contract_docx.py` |
| P1 | Аналитика автоматически включает Webvisor; внешние fonts/каналы передают technical data | Проверить законное основание/согласие и минимизацию, masking формы, фактический маршрут данных до включения рекламы |
| P1 | Воспроизводимость не битовая: широкие зависимости, изменяемые image tags, bootstrap state | Зафиксированный manifest/digests, проверка registry в РФ, rollback и SBOM/dependency review перед релизом |
| P2 | Остальные исторические runbooks/12-недельные уроки требуют построчного практического прогона | Наставник: каждый допущенный сценарий → lab → evidence; текущая выборочная ревизия не означает сертификацию всех инструкций |

## Проверки и ограничения среды

Локально: Windows, Python 3.10 в отдельном временном venv (CI Python 3.12), Node 24 (CI Node 20), Yarn 1.22.22 через npx. Backend unit suite — 54 passed; MAX alerter — 3 passed. Frontend production build успешно выполнен с `CI=true`, включая повтор после правок компонентов. DOCX пересобран из канонического Markdown. FastAPI сообщает deprecation `on_event`, это технический долг, не провал теста.

`bash -n` изменённых shell scripts выполнен через Git Bash. Это синтаксис, не интеграционный прогон backup/restore. Docker в локальной среде отсутствует: Compose/runtime/clean-room и delivery к реальным провайдерам не проверены. Доступ к production не использовался, deploy/DNS/данные не изменялись; статус развёрнутых сервисов — **Unknown** до свидетельств оператора.

Проверки документации: `validate_markdown_links.py`, `validate_business_consistency.py`, `validate_max_consistency.py`, `validate_operational_consistency.py`, `validate_deployment_freshness.py`. Они проверяют ограниченные статические инварианты, не доказывают бизнес-успех, безопасность или юридическое соответствие.

## Решение владельца

Начинать с одного оплаченного Bronze-пилота после закрытия P0, измерять все часы и расходы, отдельно подтверждать резервного инженера. Второй клиент — только после проверки мощности; Silver/Gold — по компетенциям, данным восстановления и марже. Пересмотреть ценность Silver с учётом публичного предложения Selectel от 50 тыс. ₽: нужен конкретный отличимый scope, а не обещание того же сервиса с меньшей командой.
