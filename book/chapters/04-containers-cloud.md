## VM и контейнер — разные уровни

Виртуальная машина имеет ОС, ядро, память, диск и сетевой адрес. Контейнер запускает изолированный процесс, используя ядро host. Образ — шаблон программы, контейнер — его запущенный экземпляр, том — отдельное хранение данных. Пересоздать контейнер и удалить том — разные по последствиям действия.

Dockerfile описывает сборку образа, Compose — связи сервисов. `build.context` определяет, какие файлы доступны `COPY`, а не только где лежит Dockerfile. `ports` публикует вход на host; `expose` описывает внутренний порт. Настройка `127.0.0.1:8001:8001` оставляет API доступным через loopback, перед которым работает Caddy.

## Порядок подготовки

Инвентаризация среды → версия кода → новые секреты → проверка конфигурации → основной Compose → monitoring → Caddy/статика → внутренние проверки → внешний запрос → тестовое оповещение → восстановление. Готовая VM не означает готовую услугу.

`docker compose restart` перезапускает имеющийся контейнер и не является универсальным способом применить новое окружение. Для пересоздания нужен согласованный `up -d` с проверкой diff и данных. `down -v` удаляет тома и не используется как «чистый перезапуск».

## Провайдер и стоимость

Облачный аккаунт, сеть, постоянный IP, VM, диск и snapshots — отдельные объекты расходов. Бесплатный период не делает эксплуатацию бесплатной навсегда. Локальная Astra с Wazuh не является публичным облаком и нуждается в собственном доступе/backup.

Cloud.ru и Yandex Cloud имеют разные API, квоты и сетевые ограничения. Не выполнять `yc` наугад для ресурса другого провайдера. Terraform описывает ресурсы, cloud-init готовит новую ОС, Ansible меняет состояние системы; текущий single-VM Compose не следует смешивать с альтернативным IaC без решения владельца.

## Практика и результат

В Compose выбрать backend и описать: откуда код, где секреты, какой порт, зависимость Mongo, где данные и какой запрос подтверждает готовность. Для нового сервиса сначала посчитать память/диск и общий отказ, а не просто добавить контейнер. Видео: [Docker](../VIDEO_GUIDE.md#git-и-контейнеры), [облако](../VIDEO_GUIDE.md#облако-и-рабочие-инструменты).
