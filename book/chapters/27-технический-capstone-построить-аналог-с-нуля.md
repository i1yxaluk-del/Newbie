# 27. Технический capstone: построить аналог с нуля

> **Учебная ситуация.** Теперь нельзя копировать готовый Compose целиком: нужно доказать перенос модели.

Предыдущая глава: [глава 26](./26-incident-problem-change-и-service-review.md).

## Модель, которую нужно построить

Минимальный аналог: public TLS proxy, API, persistent DB, metrics, alert webhook и encrypted backup. Компоненты можно заменить, если объяснены interfaces и recovery.

Architecture decision сравнивает варианты по требованиям, failure domains, операционной цене и обратимости. «Популярнее» не является достаточным критерием.

Definition of done включает clean restore и handover другому человеку.

## Термины в рабочем смысле

### architecture decision

Зафиксированный выбор между вариантами с requirements, trade-offs и последствиями. Это не описание уже выбранного инструмента.

### capstone

Сквозная работа без пошагового рецепта, проверяющая перенос знаний, recovery и способность обосновать решения.

### failure domain

Набор компонентов, способных отказать вместе из-за общей зависимости. Все containers на одной VM имеют общий failure domain питания, диска и host kernel.

## Что происходит внутри

В capstone сначала фиксируются requirements: число пользователей, допустимый downtime, данные, угрозы и budget. Только затем выбираются components. Замена Mongo на PostgreSQL допустима, если перепроектированы schema, backup, health и application access, а не просто изменено имя image.

## Разобранный пример

```text
Пустая VM → hardening baseline → app/data → TLS → metrics/alerts
→ backup → destructive test → clean restore → handover
```

### Как читать пример

- `Пустая VM → hardening baseline → app/data → TLS → metrics/alerts` — Стрелка показывает направление зависимости; подпись на стрелке задаёт протокол или тип передачи.
- `→ backup → destructive test → clean restore → handover` — Разделите строку на программу/оператор, options и operands; затем по документации установите side effect и exit semantics.

## Если результат не совпал с ожиданием

| Наблюдение | Что это означает | Следующая проверка |
|---|---|---|
| Работает только у автора | Это сужает область поиска, но не доказывает единственную причину | нет воспроизводимости. |
| Есть backup, нет restore | Это сужает область поиска, но не доказывает единственную причину | capstone не принят. |

## Самостоятельная работа

Решите изменённый вариант исходной ситуации: **Теперь нельзя копировать готовый Compose целиком: нужно доказать перенос модели.** Измените один существенный параметр — host, port, credential, dataset, пакет или ограничение клиента — и сначала письменно предскажите результат. Затем выполните проверку на безопасном стенде. В отчёте оставьте исходное предположение, фактическое наблюдение, причину расхождения и способ восстановления.
