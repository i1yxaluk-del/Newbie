# R-07 · SSL expired / expiring

**Severity:** P2 (expired) / P3 (expiring < 14 дней)
**Tier:** all
**Time budget:** 2 часа до renewal
**Requires:** DNS/ACME доступ, sudo на веб-серверах

---

## 1. Триггер

- Alert: `ssl_cert_expiry_days < 14`.
- Alert: клиент получил HTTPS error.
- Cron job renewal failed (certbot logs).

---

## 2. Диагностика

```bash
echo | openssl s_client -connect <host>:443 -servername <host> 2>/dev/null | \
  openssl x509 -noout -dates -subject

certbot certificates
journalctl -u certbot.timer -n 50
```

---

## 3. Действия

### 3.1. Letsencrypt (основной путь)

- [ ] `certbot renew --dry-run` — проверка без записи.
- [ ] Если dry-run passes: `certbot renew`.
- [ ] Если fails:
  - HTTP-01 challenge: проверить, что `/.well-known/acme-challenge/` доступен из интернета.
  - DNS-01 challenge: проверить API-токен (может быть expired).
  - Rate limits: если превышены — переключиться на `--staging`, потом wait.

### 3.2. Internal CA (для Gold с private services)

- [ ] Выпустить новый сертификат через PKI инструменты клиента.
- [ ] Распространить через Ansible на все серверы, где он нужен.
- [ ] Перезагрузить сервисы (nginx, apache, etc).

### 3.3. Ручной renewal (редко)

- [ ] Через панель Я.Облако / `acme.sh --renew-all`.
- [ ] Скопировать новый `.pem` на сервер.
- [ ] `nginx -t && nginx -s reload`.

---

## 4. Откат

- Если новый сертификат вызывает проблемы — вернуть старый (если ещё не expired):
  ```
  cp /etc/letsencrypt/archive/<domain>/fullchain1.pem /etc/letsencrypt/live/<domain>/fullchain.pem
  nginx -s reload
  ```

---

## 5. Проверка

```bash
echo | openssl s_client -connect <host>:443 -servername <host> 2>/dev/null | \
  openssl x509 -noout -dates
```

Ожидаем: `notAfter` ≥ 60 дней от сегодня.

Дополнительно: https://www.ssllabs.com/ssltest/analyze.html?d=<host> → ≥ A.
