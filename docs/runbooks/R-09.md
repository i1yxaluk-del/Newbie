# R-09 · User access lost (password reset)

**Severity:** P3
**Tier:** all
**Time budget:** 15 мин до восстановления доступа пользователя
**Requires:** Domain Admin (для AD) или admin на целевой системе

---

## 1. Триггер

- Клиент пишет: «Пользователь <X> не может войти / забыл пароль».
- Alert: аномально много failed logins для одного account → возможный lockout.

---

## 2. Диагностика

### 2.1. Подтвердить identity

- [ ] Запрос от ответственного сотрудника клиента (не от самого пользователя!) через официальный канал (Telegram-группа, email).
- [ ] Если сомнения — callback на официальный номер клиента (защита от social engineering).

### 2.2. Определить, где нужен reset

- AD (логины на серверы, шары).
- 1С (локальный аккаунт в 1С).
- VPN (WireGuard / OpenVPN клиент-ключ).
- Web-сервисы (почта, CRM, etc) — у каждого своя система.

### 2.3. Проверить, не lockout ли

```
# AD
Get-ADUser <user> -Properties LockedOut, PasswordExpired, PasswordLastSet
```

---

## 3. Действия

### 3.1. AD password reset

- [ ] `Set-ADAccountPassword -Identity <user> -Reset -NewPassword (ConvertTo-SecureString -AsPlainText "<temp_password>" -Force)`.
- [ ] Включить «User must change password at next logon».
- [ ] Разлочить: `Unlock-ADAccount <user>`.
- [ ] Сгенерировать **случайный** пароль (не «qwerty123»), отправить через защищённый канал (Vaultwarden temp-link, не Telegram).

### 3.2. VPN key regenerate (для WireGuard)

- [ ] Сгенерировать новую пару ключей для клиента.
- [ ] Обновить на bastion `[Peer]` секцию.
- [ ] `systemctl reload wg-quick@<interface>` (reload, не restart — чтобы не разрушить другие peer'ы).
- [ ] Отправить клиенту новый конфиг через защищённый канал.

### 3.3. Локальные учётки (Linux)

- [ ] `passwd <user>` → случайный.
- [ ] Обязать смену: `chage -d 0 <user>`.

---

## 4. Откат

- Пароль откатить нельзя (не знаем старый, он захэширован). Если пользователь не был X, а нам подсунули social-атаку — уведомить клиента, поменять процедуру.

---

## 5. Проверка

- [ ] Пользователь подтвердил, что зашёл.
- [ ] Принудительно сменил на свой пароль.
- [ ] Нет подозрительной активности из этого account за последний час.

---

## 6. Коммуникация

- Только затронутый клиент.
- Record в аудит-логе MSP (в Kaiten).

---

## 7. Post-actions

- [ ] Если lockout — проверить, не brute force ли был.
- [ ] Если пользователь теряет пароль регулярно — предложить ему password-менеджер (Vaultwarden персональный).
- [ ] Регулярная подсказка клиенту о необходимости менять пароли каждые 90 дней (или подключить MFA).

---

## 8. Security note

- ❌ **НИКОГДА** не отправлять пароли в Telegram / email незашифрованно.
- ❌ **НИКОГДА** не использовать «standard temp password» (типа `Welcome2026!`).
- ✅ Всегда rotate после первого входа (user must change).
