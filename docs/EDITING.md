# Редактирование лендинга — руководство

Этот документ — единственная точка входа для всех, кто меняет текст,
тарифы, иконки, ссылки или цвета на главной странице **mspshield.ru** (бренд
МСП Облако).

Для всего, что описано ниже, **не нужно знать React** — весь редактируемый
контент вынесен в один JSON-файл.

## 1. Архитектура: где хранится контент

```
frontend/
  src/
    content/
      landing.ru.json     ← весь редактируемый текст (заголовки, тарифы, FAQ)
      useContent.js       ← хук, отдающий контент компонентам
    components/sections/  ← визуальная разметка (трогать не нужно)
    components/icons/     ← каталог иконок (см. §5)
    pages/
      AdminLandingEdit.jsx ← UI-редактор
docs/
  EDITING.md              ← этот файл
```

**Правило:** в JSX-файлах нет хардкода текста или цен. Всё читается из
`landing.ru.json`. Если хочется поменять копию — меняйте JSON, не код.

**Override в браузере.** Файл `useContent.js` сначала берёт исходник из
репозитория, потом проверяет `localStorage["msp_landing_override"]`. Если
override есть — он применяется поверх. Это нужно UI-редактору: вы можете
поправить тарифы и сразу увидеть результат в iframe-превью, ничего не
коммитя. Чтобы изменения увидели посетители, нужно вручную скоммитить
обновлённый `landing.ru.json` в репозиторий (см. §9).

## 2. Редактирование через UI `/admin/landing-edit`

### Вход

1. Откройте `https://mspshield.ru/admin/landing-edit` (на dev: `http://localhost:3000/admin/landing-edit`).
2. Введите тот же пароль, что у `/admin/leads` (значение `ADMIN_TOKEN` на бэкенде).
3. Если уже залогинены в `/admin/leads`, редактор откроется сразу — JWT
   общий.

### Интерфейс

```
┌──────────────────────────┬──────────────────────────────┐
│   ФОРМА (слева)          │   ПРЕВЬЮ (справа)            │
│   ─────────────          │   ──────────────              │
│   ● Hero                 │  [iframe = /]                 │
│   ● Trust-strip          │   Лендинг с применённым       │
│   ● Capabilities         │   override                    │
│   ● Pricing              │                               │
│   ● Process              │                               │
│   ● Pain + Calc          │                               │
│   ● FAQ                  │                               │
│   ● Final CTA            │                               │
│   ● Nav + Footer         │                               │
│                          │                               │
│  [Скачать JSON]          │                               │
│  [Сбросить правки]       │                               │
└──────────────────────────┴──────────────────────────────┘
```

Каждая секция — раскрывающийся блок. Внутри — текстовые поля под каждое
редактируемое свойство. После любого изменения превью перезагружается
автоматически (~300 мс).

### Кнопки внизу левой панели

- **«Скачать landing.ru.json»** — формирует файл с текущими правками и
  отдаёт через браузер. Дальше: положить файл в
  `frontend/src/content/landing.ru.json` и закоммитить.
- **«Сбросить правки»** — удаляет override из браузера. Превью
  возвращается к исходнику из репозитория. **Это не отменяет уже
  закоммиченные изменения** — только локальные.

### Что важно знать про живой override

- Override лежит в `localStorage` вашего браузера. Никто кроме вас его не
  видит. Если откроете на другом устройстве — увидите исходную версию.
- Если очистить localStorage / открыть в инкогнито — override пропадёт.
- Чтобы изменения увидели все посетители — нужно скачать JSON и
  закоммитить в репозиторий.

## 3. Редактирование JSON напрямую в репозитории

Если вы умеете в Git и не любите UI — открывайте файл и правьте текст:

```bash
git checkout -b content/your-change
$EDITOR frontend/src/content/landing.ru.json
git commit -am "content: правка тарифа Bronze"
git push -u origin content/your-change
```

После мерджа в `main` → деплой пересоберёт фронт → правки видны всем.

**Правила JSON:**
- Кодировка UTF-8 без BOM.
- Двойные кавычки `"…"`, не одинарные.
- Запятая после каждого элемента, **кроме последнего** в объекте/массиве.
- Перенос строки внутри значения — `\n` (в JSON).
- Чтобы убрать секцию — нельзя удалить ключ верхнего уровня, иначе
  компонент упадёт. Можно очистить контент (`""`, `[]`), но структура
  должна остаться.

Перед коммитом провалидируйте JSON:

```bash
cd frontend && node -e "JSON.parse(require('fs').readFileSync('src/content/landing.ru.json'))" && echo "OK"
```

## 4. Структура схемы (по секциям)

Краткая карта `landing.ru.json`. Полный пример — сам файл в репозитории.

### `meta.brand`
```json
"brand": { "name": "МСП", "accent": "Облако" }
```
`name` — обычный цвет; `accent` — зелёный курсив (forest). Логотип Nav и
Footer пересобирают это.

### `nav`
```json
"nav": {
  "links": [
    { "href": "#calc", "label": "Калькулятор" },
    ...
  ],
  "cta": { "href": "#audit", "label": "Бесплатный аудит" }
}
```
Каждая ссылка — `href` (якорь `#section-id` или абсолютная ссылка) +
`label` (видимый текст). Добавьте/удалите элементы массива — пункты в
шапке появятся/уйдут.

### `hero`
```json
"hero": {
  "h1Before": "Ваша инфраструктура работает.",
  "h1Em": "Без вашего участия.",
  "lead": "...",
  "ctaPrimary":   { "href": "#audit",   "label": "Получить аудит →" },
  "ctaSecondary": { "href": "#pricing", "label": "Смотреть тарифы" }
}
```
- `h1Before` — обычный шрифт.
- `h1Em` — курсив, цвет акцента. Это вторая половина заголовка.

### `trust`
Две строки иконок. `services` — что обслуживаем (всегда `kind: service`),
`tools` — чем обслуживаем (можно смешивать `service` / `oss` / `ru`).

```json
{ "icon": "wazuh", "kind": "oss", "label": "Wazuh" }
```
`icon` — имя из каталога иконок (см. §5). `kind` определяет визуальный
стиль (geometric / open-source / RU монограмма). `label` — подпись.

### `capabilities.panels`
Массив из 4 пилонов: visibility / alerts / backups / stack. Менять
порядок и количество **нельзя** — компонент жёстко мапит индексы 0..3
на дашборды (LatencyChart, TelegramAlert+Wazuh, BackupHealth+SlaTimeline,
StackPanel). Можно менять `tab`, `title`, `em`, `bullets`.

### `pricing.plans`
3 тарифа: Bronze / Silver / Gold. Можно добавить четвёртый — см. §7.

```json
{
  "id": "bronze", "eyebrow": "Тариф 01", "name": "Bronze",
  "tagline": "1–5 серверов",
  "price": "25 000",       // без ₽ — оно дорисовывается компонентом
  "setup": "Запуск 15–25 000 ₽",
  "limit": "1–2 ч ручной работы / мес",
  "cta": "Начать с Bronze",
  "featured": false,        // выделить как «рекомендуем» (тёмная плитка)
  "features": [
    { "text": "Мониторинг 24/7", "bold": false },
    { "text": "Всё из Bronze",  "bold": true }   // bold = жирный
  ]
}
```

### `process.steps`
Массив шагов онбординга. Можно произвольно добавлять/убирать.

### `pain`
- `points` — массив строк, пуль-поинты слева в чёрной секции.
- `bronzeAnnualPrice` — число (₽), используется калькулятором простоя
  для сравнения «потери vs стоимость сервиса». Если меняете цену Bronze
  в `pricing` — поменяйте и здесь.

### `faq.items`
Список из `{ q, a }`. Порядок = порядок в аккордеоне.

### `finalCta.badges`
Массив строк под кнопками («152-ФЗ ✓», «NDA по умолчанию» и т.д.).

### `footer`
```json
"footer": {
  "tagline": "© 2026 МСП Облако · Управляемый IT-сервис",
  "legal":   "ИП Иванов И.И. · ИНН ... · ОГРНИП ...",
  "docs":    [{ "href": "/docs/privacy.html", "label": "..." }, ...],
  "email":   "hello@mspshield.ru",
  "telegram":{ "href": "https://t.me/mspshield", "label": "@mspshield" }
}
```

## 5. Иконки: какие есть, как добавить

Каталог в `frontend/src/components/icons/`. Три набора:

### `ServiceIcon` — что обслуживаем (геометрические монограммы)

| Имя             | Что это           |
|-----------------|-------------------|
| `windows`       | Windows Server (4 квадрата) |
| `ad`            | Active Directory (силуэт + кольцо) |
| `onec`          | 1С (монограмма «1С») |
| `mssql`         | MS SQL (монограмма «SQL») |
| `mail`          | Почта / DNS (конверт) |
| `fileserver`    | Файловые шары (папка) |
| `web`           | Сайт / API (глобус) |
| `database`      | PostgreSQL · MS SQL (цилиндр) |
| `vpn`           | VPN / периметр (замок) |
| `server`        | Сервер (стойка) |
| `virt`          | Виртуализация |
| `iis`           | IIS |
| `cloud`         | Облачное хранилище (облако) |
| `telegram`      | Telegram (paper-plane, канал связи) |
| `max`           | MAX (мессенджер, рамка с «M»; есть и в RuIcon) |
| `more`          | Многоточие «И другие» |

### `OssIcon` — открытое ПО (символьные mono-glyphs)

`linux`, `prometheus`, `grafana`, `loki`, `wazuh`, `ansible`, `puppet`,
`postgresql`, `nginx`, `docker`, `samba`, `wireguard`, `restic`,
`zabbix`, `freeipa`.

### `RuIcon` — РФ-ПО (кириллические монограммы)

`astra`, `redos`, `alt`, `postgrespro`, `onec`, `kaspersky`, `rucloud`,
`myoffice`, `onlyoffice`, `bitrix`, `max`.

### Как добавить новую иконку

1. Откройте `frontend/src/components/icons/ServiceIcon.jsx` (или
   `OssIcon.jsx` / `RuIcon.jsx` в зависимости от набора).
2. В объекте `SERVICES` / `PATHS` добавьте новую запись:

   ```js
   myservice: {
     kind: "shape",
     render: () => (
       <>
         <path d="M2 2 L22 22" stroke="currentColor" strokeWidth="1.6" />
       </>
     ),
   },
   ```

   Или для текстовой монограммы:
   ```js
   myservice: { kind: "monogram", text: "MS" },
   ```

3. В `landing.ru.json` пропишите её в нужной строке:
   ```json
   { "icon": "myservice", "kind": "service", "label": "Мой сервис" }
   ```
4. Соберите фронт (`yarn build`) — иконка появится.

## 6. Цвета и палитра: где менять

Цвета — НЕ в JSON. Они в `frontend/src/index.css` (CSS custom properties).

```css
:root {
  /* Базовый светлый фон лендинга */
  --cream:      #f7f4ee;
  --cream-deep: #efe9dc;

  /* Текст */
  --ink:    #1a1815;   /* основной текст */
  --ink-2:  #2c2a26;   /* вторичный */
  --stone:  #58524a;   /* подсказки, лейблы */
  --stone-lt: #8a8278; /* самый лёгкий тон */

  /* Акцент бренда */
  --forest: #1b4d3e;

  /* Линии и сетки */
  --rule:    rgba(26,24,21,.10);
  --rule-lt: rgba(26,24,21,.06);

  /* Шрифты */
  --fd: "Source Serif Pro", serif;      /* h1, h2, h3 */
  --fb: "Inter", sans-serif;            /* body */
  --fm: "JetBrains Mono", monospace;    /* tag-dot, eyebrow */
}
```

**Тёмные секции** (Pricing, Pain, FinalCta) используют локальные
hex'ы `#0e0c0a` / `#1b4d3e` / `#5fc9a2` прямо в JSX — они визуально
противопоставлены `--cream`-фону, поэтому не вынесены в CSS-переменные.

### Как сменить акцентный цвет

1. Откройте `frontend/src/index.css`.
2. Поменяйте `--forest`. Например: `--forest: #c2410c;` → оранжевый.
3. Соберите фронт.

Всё, что использует `var(--forest)` — логотип, primary CTA, акцентные
курсивы — обновится автоматически.

## 7. Как добавить новый тариф

Пример: добавляем тариф «Platinum» между Silver и Gold.

1. Откройте `frontend/src/content/landing.ru.json` (или работайте через
   UI — структура такая же).
2. В `pricing.plans` вставьте новый объект:

   ```json
   {
     "id": "platinum",
     "eyebrow": "Тариф 03 · enterprise",
     "name": "Platinum",
     "tagline": "Multi-site · 24×7 on-call · custom SLA",
     "price": "150 000",
     "setup": "Запуск от 80 000 ₽",
     "limit": "выделенная команда",
     "cta": "Узнать про Platinum",
     "featured": false,
     "features": [
       { "text": "Всё из Gold",                 "bold": true  },
       { "text": "Выделенный инженер 24×7",     "bold": false },
       { "text": "Кастомный SLA по согласованию","bold": false },
       { "text": "Quarterly business review",   "bold": false },
       { "text": "Реакция P1 — до 30 мин",      "bold": true  },
       { "text": "DR-площадка в отдельном ДЦ",  "bold": false }
     ]
   }
   ```

3. **Важно:** карточка использует CSS-grid `repeat(3, 1fr)`. Если планов
   станет 4 — поправьте `gridTemplateColumns` в
   `frontend/src/components/sections/Pricing.jsx` на `repeat(4, 1fr)`
   (на мобилке адаптив уже сделан).
4. Если у тарифа другая годовая цена для сравнения в калькуляторе
   простоя — обновите `pain.bronzeAnnualPrice` (или оставьте как есть —
   калькулятор привязан именно к Bronze).
5. Соберите → проверьте → коммит.

Чтобы убрать тариф — удалите соответствующий объект из массива. Grid
автоматически перестроится.

## 8. Как заменить иконку (например, Prometheus → Zabbix)

1. Откройте `landing.ru.json`.
2. Найдите в `trust.tools` объект с `"icon": "prometheus"`.
3. Замените:
   ```json
   { "icon": "zabbix", "kind": "oss", "label": "Zabbix" }
   ```
4. Если такой иконки нет в каталоге (`OssIcon.jsx`) — добавьте её по
   инструкции из §5.
5. Коммит → деплой.

## 9. Деплой и применение изменений

После любых изменений (через UI или прямой правкой JSON):

```bash
# 1. Если редактировали через UI — сохраните скачанный файл:
mv ~/Downloads/landing.ru.json frontend/src/content/landing.ru.json

# 2. Закоммитьте:
git add frontend/src/content/landing.ru.json
git commit -m "content: ..."

# 3. Запушьте — CI/CD пересоберёт фронт автоматически:
git push origin main      # или через PR — рекомендуем
```

Для production-сборки локально:

```bash
cd frontend
yarn build
# build/ готов к деплою на nginx / Vercel / static-хост
```

После деплоя проверьте `https://mspshield.ru/` — изменения видны всем
посетителям, не зависят от их localStorage.

## 10. FAQ редактора

**Q: Я поправил тарифы через UI, но друг видит старые цены.**
A: Через UI правки сохраняются только в *вашем* браузере. Чтобы их увидели
все — скачайте JSON и закоммитьте в репозиторий (§2 → «Скачать
landing.ru.json»).

**Q: Я обновил JSON в репо, но в браузере вижу старую версию.**
A: У вас в `localStorage` есть override, который перекрывает репозиторий.
Откройте `/admin/landing-edit` → «Сбросить правки» или вручную:
`localStorage.removeItem('msp_landing_override')` в DevTools Console.

**Q: Я случайно удалил поле и лендинг не открывается.**
A: Восстановите `landing.ru.json` из истории Git
(`git checkout HEAD -- frontend/src/content/landing.ru.json`). Если речь
о localStorage-override — очистите его в DevTools.

**Q: Можно ли перевести лендинг на английский?**
A: Положите рядом `landing.en.json` с такой же структурой и доработайте
`useContent.js`, чтобы он выбирал файл по `lang`. Это не входит в
текущий контракт MVP.

**Q: Где менять текст 152-ФЗ-бейджей?**
A: `finalCta.badges` (массив строк). Сейчас 4 элемента.

**Q: Как поменять Telegram-канал в Footer?**
A: `footer.telegram.href` + `footer.telegram.label`.

**Q: Email в Footer берётся из JSON или из бэкенда?**
A: Из JSON (`footer.email`). Email для приёма заявок — отдельная
настройка `backend/.env`. Эти два значения не связаны автоматически.

**Q: Как поменять favicon / og:image?**
A: Не через JSON. Файлы лежат в `frontend/public/`. Замените их и
пересоберите.

**Q: Калькулятор простоя — где формула?**
A: Формула в коде (`Pain.jsx`), её менять только разработчику. Через JSON
правится только дефолтное значение `bronzeAnnualPrice` и текст
заголовков.

## Чек-лист «сделал — не сломал»

Перед коммитом изменений в `landing.ru.json`:

- [ ] JSON-валидатор не ругается: `node -e "JSON.parse(require('fs').readFileSync('frontend/src/content/landing.ru.json'))" && echo OK`
- [ ] `cd frontend && yarn build` — сборка прошла без ошибок
- [ ] Лендинг в браузере открывается, текст в нужных местах
- [ ] Нет «undefined» в видимых местах (значит, поле случайно стёрто)
- [ ] Все ссылки `href` работают (якоря существуют, внешние URL открываются)
- [ ] Сборка не увеличилась критически (норма: 140–145 KB JS gzip)
