# 6. Ситуации из практики сопровождения

[← Курс](README.md) · [Правила эксплуатации](07_OPERATIONS.md)

## 1. Изменился важный файл

**Ситуация:** FIM сообщил об изменении `training-policy.txt`. Назначение FIM — сравнить контролируемое состояние, а не угадать намерение человека.

Проверить путь, узел, время, тип изменения, доступные hashes/атрибуты. Затем найти разрешённое изменение с тем же временем. В lab генератор намеренно меняет этот файл; это ожидаемый результат. Для клиента отсутствие заявки требует выяснения, но не позволяет автоматически обвинить сотрудника.

**Практика:** провести два запуска генератора под наставником, сравнить добавление/изменение и записи конкретного run_id. FIM-событие не обязано содержать этот JSON run_id: сопоставление выполняется также по файлу и времени. Не обещать побайтовую разницу содержимого, если сбор diff не включён.

**Лучший приём:** начать с небольшого перечня критичных конфигураций. Полный `/` создаст шум, нагрузку и сбор лишних данных. Исключение пути оформлять с причиной/владельцем/датой пересмотра, не выключать весь FIM.

## 2. Много неудачных входов

Это может быть ошибка пароля, сломанная служебная учётка, сканирование либо подбор. Нужны источник, пользователь, длительность, успешный вход после ошибок, назначение узла. Одна серия ошибок не доказывает компрометацию.

**Безопасная практика:** наставник выдаёт вымышленные строки журнала для `wazuh-logtest`; реальный подбор пароля не выполняется. Проверить, какой декодер распознал строку, какое правило выбрано и нужны ли повторения для корреляционного правила. Не выдавать собственное правило с похожим названием за проверенную штатную корреляцию.

**Решение:** зарегистрировать наблюдение, сопоставить с допустимой активностью и эскалировать по контексту. Автоблокировка адреса может отключить VPN/NAT нескольких пользователей: включение Active Response — отдельный проект, не обязательный шаг Junior.

## 3. Сигнал об ошибке backup

В lab правило 100101 реагирует на синтетическую строку. Чтобы сделать настоящее наблюдение, необходим реальный источник результата задания: код завершения, время последней успешной копии, репозиторий, объект. Нельзя заменить отсутствие реальной копии периодическим «успешным» сообщением.

Проверить: задача действительно запускалась? хранилище доступно? есть другие пригодные копии? нарушена ли согласованная допустимая потеря данных? Не запускать prune/удаление истории из-за красной карточки. Сам Wazuh копии не создаёт и не восстанавливает. Результат сквозного упражнения: источник → правило → индекс → уведомление → ответственное лицо.

## 4. Найдена уязвимость приложения

Механизм зависит от сведений об установленном ПО и источника данных об уязвимостях. Сначала определить реальный узел/ОС, версию пакета, CVE, доступность уязвимого компонента и наличие исправления у поставщика. Версия с перенесённым исправлением может отличаться от сравнения по одному номеру; проверить бюллетень поставщика.

**Практика:** разбор заранее подготовленного отчёта наставника без установки заведомо уязвимого сервиса. Отдельно отметить, есть ли обновлённый inventory/feed. Пустой список при неработающем feed не является чистым результатом.

**Решение:** согласованное обновление через Ansible после backup, окна и прикладной проверки. Нельзя запускать полное обновление всей среды из dashboard по одному сигналу.

## 5. SCA показывает много нарушений

Сначала проверить, кого оценивали: на текущем стенде — ОС manager-контейнера. Рекомендации по ядру/загрузчику внутри контейнера могут быть неприменимы. Высокая доля выполненных проверок не равна соответствию 152-ФЗ; низкая доля не всегда означает немедленную аварию.

**Практика:** выбрать три проверки, для каждой выписать цель, условие, проверяемый объект, применимость, риск исправления и способ подтверждения. Итог — обоснованная рекомендация или документированное исключение, а не автоматическое применение всех советов.

## 6. Событие есть в журнале, но отсутствует в поиске

Проверять по цепочке из [теории](05_EVENT_THEORY.md), начиная с известного run_id и времени. Если manager сформировал оповещение, генерация нового не исправит Filebeat. Если индекс содержит документ, перезапуск manager не исправит фильтр времени.

**Практика:** наставник выдаёт один из симптомов и доступ только на чтение. Ученик формулирует следующий проверяемый шаг и ожидаемое различие двух гипотез. Не перезапускать все контейнеры одновременно: потеряете причинную связь и усложните диагностику.
