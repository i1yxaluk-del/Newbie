## Что выполняется в браузере

HTML задаёт структуру, CSS — оформление, JavaScript — поведение. React собирает интерфейс из компонентов; маршрут выбирает страницу без полной перезагрузки. В проекте CRA работает через CRACO, а не Vite/Next. Сборка превращает исходники в готовую статику.

`REACT_APP_*` подставляются при сборке и видны пользователю: это не место для серверных паролей. Пустой backend URL использует `/api` того же домена. Параметры CAPTCHA в браузере и на сервере должны принадлежать совместимой настройке.

## Где менять слова

`landing.ru.json` содержит большую часть контента. Некоторые тексты остаются в JSX, SEO/JSON-LD — в `public/index.html`, публичные условия — в HTML. Редактор сохраняет черновик в localStorage этого браузера и скачивает JSON; он не публикует файл на сервер. Массив в черновике заменяет прежний целиком; правильный JSON не обязательно соответствует ожидаемой структуре.

Хороший лендинг объясняет: кому полезно → какой результат → границы → стоимость/отдельные расходы → как начать. Демонстрационный график должен быть помечен, а не выдаваться за текущие клиентские метрики.

## Форма и доверие

Браузерные проверки помогают человеку, но запрос можно отправить напрямую. API повторно проверяет поля, согласие, CAPTCHA и ограничения частоты. Политика и отдельное согласие должны содержать реального оператора и фактические системы обработки; пока реквизиты не утверждены, документы остаются проектами.

## Публикация

Проверить текст/обещания → собрать → сохранить прежнюю версию → доставить → открыть внешний URL и ресурсы → проверить форму на разрешённом target. Старые вкладки могут запросить старый lazy chunk, поэтому публикация сохраняет hashed assets. Наличие нового коммита не обновляет `/var/www/landing` автоматически.

Практика: маркетолог меняет одну фразу без изменения цены, владелец проверяет diff/сборку, второй человек сверяет опубликованную страницу. Обучение: [веб и React](../STACK_AND_LEARNING.md), [реклама и аналитика](../VIDEO_GUIDE.md#маркетинг-и-управление).
