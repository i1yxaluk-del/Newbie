# Каталог типовых сервисов клиентов

> **Для кого этот документ.** Junior-инженер MSPShield, который первый раз пришёл к клиенту
> и должен понять: какие сервисы обслуживать, как их принимать, подключать и контролировать.
>
> **Принцип:** мы не «настраиваем сервис с нуля» — мы **принимаем и обслуживаем**.
> Разворачиванием с нуля занимается клиент или интегратор (1С-франчайзи, хостер сайта).
> Наша задача — мониторинг, бэкапы, SLA, документация, рекомендации по улучшениям.

## Типовой сервисный ландшафт B2B-клиента

Средний клиент MSPShield (15–150 сотрудников) обычно имеет:

| Сервис | Частота | Критичность для бизнеса | Наш файл |
|---|---|---|---|
| **Корпоративный сайт / лендинг** | 95% клиентов | Средняя (марка, заявки) | [`website.md`](./website.md) |
| **1С:Предприятие (сервер)** | 70% клиентов | **Критическая** (остановка = потеря выручки) | [`1c_server.md`](./1c_server.md) |
| **Active Directory (Windows)** | 55% клиентов | Критическая (аутентификация всех) | [`ad_domain.md`](./ad_domain.md) |
| **FreeIPA (Linux)** | 10% клиентов (рост в 2026) | Критическая | [`freeipa_domain.md`](./freeipa_domain.md) |
| **Почта + DNS** | 90% клиентов | Высокая | [`mail_dns.md`](./mail_dns.md) |
| **Файловый сервер (Samba/Windows)** | 80% клиентов | Высокая | [`file_server.md`](./file_server.md) |
| **База данных (Postgres / MS SQL)** | 60% клиентов | Критическая | [`database.md`](./database.md) |

## Общий алгоритм: «как работать с любым сервисом клиента»

Для **каждого** сервиса у нас один и тот же 5-шаговый цикл:

```
1. ПРИЁМ (DISCOVERY)     → описать что есть (inventory)
2. ПОДКЛЮЧЕНИЕ (CONNECT) → поставить агент / exporter / WireGuard
3. НАСТРОЙКА (TUNE)      → пороги алертов, dashboard, runbook
4. КОНТРОЛЬ (MONITOR)    → weekly-отчёт, SLA, регулярные проверки
5. TROUBLESHOOT          → стандартный протокол при проблеме
```

Каждый файл каталога следует этой же структуре. Junior изучает 1 сервис за 2–3 часа
и готов его принимать/обслуживать.

## Связь с тарифами

| Сервис | Входит в Bronze | Входит в Silver | Входит в Gold |
|---|:-:|:-:|:-:|
| Мониторинг (uptime, CPU, RAM, диск, сеть) | ✓ | ✓ | ✓ |
| Бэкапы по расписанию | ✓ | ✓ | ✓ |
| Централизованные логи | — | ✓ | ✓ |
| Автоматизация конфигов (Puppet/Ansible) | — | ✓ | ✓ |
| Управление учётками AD/FreeIPA | — | ✓ | ✓ |
| Security-детект (SIEM) | — | — | ✓ |
| EDR (Kaspersky) | — | — | ✓ |

## Связь с бизнес-моделью

Сервисы клиента — это **источник allocation и upsell**:
- Клиент на Bronze захотел централизованные логи → предложить апгрейд на Silver (+25k₽)
- На Silver нужна защита периметра (152-ФЗ) → апгрейд на Gold (+35k₽)
- Сверх лимита часов — [`ADDONS.md`](../../ADDONS.md) (миграция 1С, аудит безопасности, обучение)

## Шаблон inventory для клиента

Когда принимаем клиента, для каждого сервиса заводим запись в `clients/<slug>.yml`:

```yaml
client: example-llc
tariff: silver
services:
  - type: website
    name: example.ru
    owner_ext: hoster-timeweb
    uptime_sla: 99.5%
    criticality: medium
    backup: managed_by_hoster
  - type: 1c_server
    hostname: srv-1c-01
    ip: 10.9.0.15
    platform: "1C 8.3.25 + PostgresPro 15"
    db_size_gb: 42
    users_peak: 35
    backup_retention: 30d
    criticality: critical
  - type: ad_domain
    dc_primary: srv-dc-01
    dc_secondary: srv-dc-02
    domain: example.local
    users: 58
    criticality: critical
```

Этот файл читается `scripts/onboard_client.sh` и автоматически наполняет
`prometheus.yml`, `restic.conf`, Ansible inventory.
