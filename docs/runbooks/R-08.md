# R-08 · VPN/AmneziaWG tunnel down

**Severity:** P2
**Tier:** all
**Time budget:** 30 мин до восстановления
**Requires:** root на bastion + клиентском gateway

> Этот раннбук покрывает **AmneziaWG** — российский форк WireGuard с
> обфускацией handshake против РКН-DPI. Слушает на **UDP/443** (не
> конфликтует с Caddy TCP/443 на той же VM). См.
> `technical/0_Common/amneziawg/`.

---

## 1. Триггер

- Alert: `wireguard_latest_handshake_seconds > 300` (метрика собирается
  тем же `prometheus-wireguard-exporter` — он совместим с `awg`-интерфейсом,
  потому что nl80211 socket такой же).
- Alert: peer endpoint unreachable.
- Клиент сообщает: «Не могу подключиться к офису через VPN».

---

## 2. Диагностика

```bash
# На bastion (AmneziaWG)
awg show
awg show <interface> latest-handshakes
ip route
systemctl status awg-quick@<interface>

# На клиентском gateway (если есть)
awg show
systemctl status awg-quick@<interface>
```

Где `<interface>` — обычно `awg0` (на bastion) или `awg0-msp` (на клиенте).

---

## 3. Действия

### 3.1. Peer не coming up

- [ ] Проверить, что endpoint IP корректный.
- [ ] Проверить, что **UDP/443** открыт в security group (обе стороны):
      `sudo ufw status | grep '443/udp'` на bastion.
- [ ] Проверить, что keys не rotated без нашего ведома.
- [ ] `systemctl restart awg-quick@<interface>` на обеих сторонах.

### 3.2. Tunnel up, но трафик не идёт

- [ ] `iptables -L -n -v` — нет ли правил, блокирующих forwarding.
- [ ] `sysctl net.ipv4.ip_forward` → должно быть 1.
- [ ] AllowedIPs в конфиге правильные?
- [ ] MTU (иногда нужно `MTU = 1420` явно).

### 3.3. Множественные клиенты offline

- [ ] На bastion: перезапустить сервис AmneziaWG (`systemctl restart awg-quick@awg0`).
- [ ] Если не помогает: проверить load на bastion (CPU, RAM, conntrack).
- [ ] Network:  не поменялся ли публичный IP bastion?

### 3.4. Handshake вообще не приходит (РКН/Yandex Cloud режут трафик)

Признак: tcpdump на bastion ничего не видит на UDP/443, при этом
клиент находится в РФ. AmneziaWG специально создан против DPI, но
если параметры обфускации НЕ совпадают на сервере и клиенте —
handshake не пройдёт.

- [ ] **Сверить 9 параметров** Jc/Jmin/Jmax/S1/S2/H1..H4 на bastion
      и у клиента (они должны быть идентичны).
      Команда на bastion:
      ```bash
      grep -E '^(Jc|Jmin|Jmax|S1|S2|H1|H2|H3|H4) ' /etc/amnezia/amneziawg/awg0.conf
      ```
      Та же команда на клиенте. Различие → клиент пере-генерировать
      конфиг через `tenant_add.sh` или `onboard_client.sh` (они читают
      параметры с сервера автоматически).
- [ ] Проверить, что DKMS-модуль реально загружен:
      `lsmod | grep amneziawg`. Если пусто — DKMS не пересобрался
      после обновления ядра. Откатить ядро (см. R-05) или пересобрать
      модуль: `apt-get install --reinstall amneziawg-dkms`.

### 3.5. Откат на vanilla WireGuard (Plan B)

Если AmneziaWG не стартует после обновления ядра и нет времени
разобраться — временно переключиться на WireGuard (старые конфиги
в git под `technical/0_Common/wireguard/` сохранены для rollback):

```bash
systemctl stop awg-quick@awg0
apt-get install -y wireguard wireguard-tools
# Скопировать /etc/amnezia/amneziawg/awg0.conf → /etc/wireguard/wg0.conf
# Убрать строки Jc/Jmin/Jmax/S1/S2/H1..H4 (WG их не понимает)
sed -i -E '/^(Jc|Jmin|Jmax|S1|S2|H1|H2|H3|H4)\s*=/d' /etc/wireguard/wg0.conf
# Сменить ListenPort 443 → 51820 (или другой, если WG-клиенты ожидают)
systemctl enable --now wg-quick@wg0
# В Terraform/SG открыть UDP/51820 временно.
```

Это **временно**. Клиенты внутри РФ через WireGuard может не пройдёт
вовсе из-за DPI — fallback работает только если клиенты вне РФ или
у их провайдера DPI ещё не догнал.

---

## 4. Откат

- Если меняли конфиг — вернуть прошлую версию из git:
  ```
  cd /etc/amnezia/amneziawg/ && git log --oneline -5
  git checkout <prev_commit> -- <interface>.conf
  systemctl restart awg-quick@<interface>
  ```

---

## 5. Проверка

- [ ] `awg show` — handshake < 180 сек.
- [ ] `ping` через tunnel до внутренних адресов работает.
- [ ] Клиент подтверждает.
- [ ] Prometheus alert зелёный.

---

## 6. Коммуникация

- Если multiple tenants затронуты (bastion-issue) — сообщение всем.
- Если 1 клиент — только ему.

---

## 7. Post-actions

- [ ] Если bastion перегружен — либо масштабировать, либо вынести часть tenant'ов в 2-й bastion.
- [ ] Регулярная ротация ключей (раз в год) — напомнить.
- [ ] Если причина в cloud-провайдере (сеть) — зафиксировать, eskalate в support.
- [ ] Если DKMS-модуль не пересобрался после kernel-update — поставить hold
      на ядро (см. R-05) или перевести VM на LTS-ядро.
