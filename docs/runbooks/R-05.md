# R-05 · AD replication failure

**Severity:** P2
**Tier:** Silver / Gold
**Time budget:** 2 часа до восстановления репликации
**Requires:** Domain Admin, доступ к DC (RDP / console), Ansible inventory

---

## 1. Триггер

- Alert из Prometheus AD-exporter: `ad_replication_lag_seconds > 3600`.
- `repadmin /showrepl` показывает ошибки.
- `dcdiag /test:Replications` fails.
- Пользователи жалуются, что пароль не проходит на одном DC, но проходит на другом.

---

## 2. Диагностика

```
dcdiag /v /c
repadmin /showrepl
repadmin /replsummary
dcdiag /test:DNS
dcdiag /test:FSMO
netdiag
```

**Типичные ошибки:**
- DNS-проблема (SRV-записи отсутствуют).
- Network (порт 389/636/445/88 блокируется).
- Time skew > 5 мин (Kerberos ломается).
- Tombstone lifetime превышен (lingering objects).

---

## 3. Действия

### 3.1. DNS-проблема

- [ ] Проверить `_ldap._tcp.dc._msdcs.<domain>` SRV-записи.
- [ ] Перерегистрация: `ipconfig /registerdns` + `nltest /dsregdns` на каждом DC.
- [ ] Перезапустить «DNS Server» и «Netlogon» службы.

### 3.2. Сетевые блоки

- [ ] Проверить, что порты 389, 636, 88, 445, 3268, 3269 открыты между DC.
- [ ] Firewall на DC: не блокирует ли security-group в cloud.

### 3.3. Time skew

- [ ] `w32tm /query /status` на всех DC.
- [ ] Перенастроить: forest PDC emulator → time.windows.com (или NTP.ru).
- [ ] `w32tm /resync` на каждом DC.

### 3.4. Lingering objects

- [ ] `repadmin /removelingeringobjects` с правильным reference DC.

### 3.5. Force replication

- [ ] `repadmin /syncall /A /e /P` (full push).
- [ ] Подождать 15 мин, повторить `repadmin /showrepl`.

---

## 4. Откат

- Если ручное вмешательство привело к inconsistency — seized FSMO roles
  на здоровый DC, демоутировать больной.
- Worst case — demote и вернуть как новый DC (4 часа).

---

## 5. Проверка

- [ ] `repadmin /replsummary` — 0 ошибок.
- [ ] `dcdiag` — все тесты passed.
- [ ] Изменение на одном DC появляется на других в течение 15 мин.
- [ ] Пользователи могут логиниться на любой DC.

---

## 6. Коммуникация

- Обычно клиенту мы не говорим об AD-репликации (это наша «кухня»).
- Если был downtime logon'ов для пользователей — сообщение и post-mortem.
