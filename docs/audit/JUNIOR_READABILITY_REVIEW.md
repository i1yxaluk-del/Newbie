# Достаточность пояснений для Junior: ревизия

## Вывод

**High:** пояснений во всём проекте недостаточно, чтобы начинающий инженер самостоятельно понимал назначение каждой функции, переменной и операции. В отдельных файлах хорошие вводные уже есть, но они не всегда соответствуют коду. Количество комментариев не доказывает пригодность для обучения.

Выполнены два разных вида проверки:

1. **Сплошной машинный обход** отслеживаемых исходников/конфигураций: [реестр](JUNIOR_SOURCE_INVENTORY.md), [генератор](../../scripts/audit_junior_readability.py). Он отмечает файлы без строк комментариев и Python-функции без docstring. Архив, зависимости и сборочные файлы исключены. Содержимое/секреты не выводятся.
2. **Ручной разбор ключевых цепочек:** API/очередь/Kaiten, контент frontend/аналитика, MAX/Matrix-доставка, Wazuh preparation/start/translation, календарь, Ansible entrypoint/inventory/роль baseline/restic/monitoring и patch-сценарии. Это не построчная экспертиза всех сотен файлов из реестра.

## Подтверждённые пробелы и исправления

| Область | Недостаток | Что сделано / остаток |
|---|---|---|
| Production API | Английские вводные, неочевидная подмена функций и очередь | Русские контракты всех функций secure_server; объяснены ASGI, pending, marker, UTC, повторы и один worker |
| Kaiten | Не описаны границы None/lookup и защита от дублей | Контракты функций, источники окружения и отличие поиска от атомарной гарантии |
| Frontend content | Комментарий обещал отсутствующую связь re-render и безопасность структуры | Исправлены утверждения; объяснены местный черновик, замена массивов и необходимость проверки схемы |
| Аналитика | Нет объяснения времени подстановки env/смысла цели | Добавлены комментарии о сборке CRA, данных и отсутствии счётчика |
| Wazuh | Смешаны названия host/container, три пароля и bootstrap | Комментарии этапов prepare/start, регистрация i18n; отдельная теория полей/правил и случаев |
| Backup calendar | Неочевидны два времени и tuple | Docstrings query/calendar/render/main, разница дня запуска и дня наблюдения |
| Matrix alerter | health/частичный успех выглядят как end-to-end проверка | Контракты всех функций и пояснение ограничений; блокирующий HTTP и частичная доставка требуют отдельной доработки |
| Ansible | Неверные гарантии в комментариях | Указан альтернативный контур, действительный набор тегов/узлов, риск SSH/UFW и перезапуска служб при apt |
| Ansible secrets/init | Таймер до init, snapshots failure смешан с отсутствием repo | Явно разобрано в курсе/комментариях; поведение в этой учебной задаче не изменено, production-допуска нет |
| Ansible SSH | host_key_checking=False | Помечено как небезопасное историческое значение; реальное выполнение требует known_hosts и включённой проверки. Изменение поведения/живых доступов в этой задаче не выполнялось |
| Matrix invite/QR | Большие файлы, смешение UI/БД/криптографии, мало русских объяснений | Карта чтения и границы Junior; нужен отдельный разбор состояний/секретов и протокольные тесты перед самостоятельным сопровождением |
| Прочие роли/старые scripts | Английские task names, неявные права и зависимости | Реестр для планирования; каждый допущенный сценарий требует своего ручного разбора, не массовой вставки комментариев |

## Что не стоит делать

Не добавлять искусственный комментарий к каждой строке ради счётчика; не переводить API field names; не объявлять JSON «непонятным» только из-за отсутствия комментариев; не переписывать криптографический/аварийный код без теста; не исполнять production scripts ради проверки их назначения.

## Приоритет последующих разборов

1. Перед доступом Junior: конкретные изменяющие скрипты из его разрешённого перечня (входы, права, возврат), SSH/backup/удаление аккаунтов.
2. До нового клиентского Ansible: порядок restic init/timer, ограничение hosts, корректность повторного Mongo admin, совместимость ОС/коллекций, checksum/version установки сборщика журналов.
3. До сопровождения Matrix: схема состояний invite/OIDC/QR и прав MAS/Synapse, отрицательные проверки, персональные сессии и отзыв.
4. Затем оставшиеся роли, правила monitoring и вспомогательные приложения по реестру; каждому — владелец и практическое доказательство. Наличие docstring только повод для чтения, не автоматический допуск.

- Реестр: 361 исходный/конфигурационный файл, 70 архивных исключены; число docstring учитывается отдельно от строк комментариев.
- Ссылки: 42 документа; все пять профильных валидаторов пройдены.

- Функциональное выполнение новой песочницы, проверка ролей Ansible на целевой ОС и практические занятия Wazuh этой редакцией не заявлены выполненными. Комментарии уточняют существующее поведение, не исправляют все найденные эксплуатационные недостатки.
