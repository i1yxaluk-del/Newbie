# Процессы: кто кому что передаёт

[← Книга](BOOK.md)

| Процесс | Вход и зависимости | Владелец → получатель | Проверяемый выход |
|---|---|---|---|
| Исследование рынка | Узкий сегмент, допустимые контакты, вопросы о прошлом опыте | Маркетолог → владелец | Цитаты/факты, альтернативы, гипотеза спроса; не выдуманный TAM |
| Кампания | Проверенный оффер, готовая форма/ПДн, бюджет/маркировка, способ измерения | Маркетолог → продажи | Подходящие обращения с источником, затраты/следующее решение |
| Квалификация | Потребность, полномочия, сроки, бюджет/окно | Менеджер → инженер | Назначенное обследование или причина отказа |
| КП и договор | Периметр, часы/цена/НДС, мощность, права/данные | Владелец/юрист → клиент | Подписанные приложения, оплата и критерии запуска |
| Подключение | Договор/контакты, персональные доступы, разрешение на изменения | Инженер → менеджер/клиент | Inventory, test alert, прикладной restore, открытые риски и приёмка |
| Изменение | Одобрение, backup/окно, исходное состояние, возврат | Инженер + reviewer → клиент | Прикладная проверка, обновлённая конфигурация и журнал |
| Инцидент | Наблюдение/обращение, периметр/приоритет, доступ/резерв | Incident owner → клиент | Timeline, диагностика/восстановление, проверка и задачи предотвращения |
| Регулярный отчёт | Согласованные объекты, часы, incidents/changes, backup evidence | Менеджер + инженер → клиент | Понятный результат, отклонения/план, акт; не просто число alerts |
| Продление/рост | Фактическая ценность/часы, новый scope, риски/цена | Владелец → клиент | Пересогласование либо завершение без скрытого роста обязательств |
| Завершение | Уведомление, план передачи/retention, владелец recovery | Владелец/инженер → клиент | Документация/копии, отзыв прав, итоговый расчёт и удаление по основаниям |

## Минимум записи для любого действия

Дата/ответственный → объект/среда → источник разрешения → ожидаемый результат → сделанное → фактическая проверка → остаточный риск/следующий шаг. Секреты не записываются в карточку, клиентские сведения не попадают в публичный Git.

Если передача не состоялась, это не «проблема коммуникации», а незавершённый процесс с риском услуги. В маленькой команде один человек может исполнять несколько ролей, но этапы и доказательства всё равно разделены.
