# Git и GitHub: как безопасно менять проект

Git хранит версии файлов. GitHub показывает эти версии команде и запускает автоматические проверки.

Представьте, что вы изменили инструкцию по развёртыванию. Если просто заменить файл на сервере, через месяц никто не вспомнит, что именно поменялось. Git сохраняет изменение вместе с автором, временем и пояснением.

## Репозиторий, коммит и ветка

Репозиторий — папка проекта вместе с историей изменений.

Коммит — сохранённый набор изменений. У каждого коммита есть номер. По нему можно открыть точную версию проекта.

Ветка — отдельная линия работы. Она позволяет готовить изменение, не вмешиваясь сразу в основную версию `main`.

## Сначала смотрим состояние

```bash
git status --short
```

Команда показывает изменённые файлы. Она ничего не меняет. Буква `M` означает изменение, `??` — новый файл, который Git ещё не отслеживает.

```bash
git diff
```

Команда показывает строки, которые были добавлены или удалены. Перед сохранением изменений прочитайте весь вывод.

## Создаём отдельную ветку

```bash
git switch -c docs/mail-runbook
```

`switch` переключает ветку. Параметр `-c` создаёт новую. Имя `docs/mail-runbook` объясняет цель работы.

Теперь измените один документ и снова выполните `git diff`.

## Выбираем файлы и создаём коммит

```bash
git add docs/runbooks/R-smtp-down.md
git commit -m "docs: уточнить восстановление почты"
```

`git add` выбирает файл для следующего коммита. Он ещё ничего не отправляет в GitHub.

`git commit` сохраняет выбранные изменения в локальной истории. Текст после `-m` отвечает на вопрос: что изменилось?

## Отправляем ветку в GitHub

```bash
git push -u origin docs/mail-runbook
```

После этого в GitHub можно открыть Pull Request — предложение добавить ветку в `main`.

Перед объединением посмотрите список файлов, сами изменения и результаты автоматических проверок. Зелёная проверка означает только то, что выполненные тесты прошли. Она не заменяет чтение текста и проверку живого сервера.

## Как отменить неудачное изменение

В общей ветке безопаснее создать новый коммит, который отменяет старый:

```bash
git revert НОМЕР_КОММИТА
```

Не используйте `git reset --hard`, пока не понимаете, какие локальные изменения и версии он удалит.

## Практика

1. Создайте учебную ветку.
2. Измените одну строку в копии документа.
3. Проверьте `git status` и `git diff`.
4. Создайте коммит.
5. Откройте Pull Request.
6. Прочитайте изменения так, будто их сделал другой человек.
7. Отмените коммит через `git revert`.
