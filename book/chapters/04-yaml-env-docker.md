# YAML, переменные окружения и Docker

YAML — текстовый формат настроек. В нём важны отступы. Два пробела могут означать вложенность, а табуляция часто ломает файл. Перед изменением найдите родительский раздел и посмотрите соседние строки.

Файл `.env` хранит значения переменных: адреса, режимы и секреты. Он не должен попадать в Git. Файл `.env.example` содержит только названия и безопасные примеры.

Docker запускает приложение в контейнере. **Образ** — подготовленный набор файлов. **Контейнер** — запущенный экземпляр образа. **Том** — отдельное хранилище данных. **Сеть Docker** позволяет контейнерам обращаться друг к другу по имени.

Compose-файл описывает несколько контейнеров как систему. Команда:

```bash
docker compose config
```

собирает итоговую конфигурацию и находит ошибки YAML. Она не запускает сервисы. Не публикуйте результат, если туда подставились секреты.

```bash
docker compose up -d
```

создаёт или обновляет контейнеры и оставляет их работать в фоне. После изменения `.env` простой `restart` недостаточен: старый контейнер может сохранить прежние переменные. Используйте пересоздание и затем проверяйте фактическое состояние.

```bash
docker compose ps
docker compose logs --tail 100 backend
```

Первая команда показывает контейнеры. Вторая читает последние строки журнала `backend`.

Том нельзя считать резервной копией: он находится рядом с приложением и может быть потерян вместе с сервером.

## Практика

Создайте учебный Compose с веб-сервисом и томом. Перезапустите контейнер и убедитесь, что данные сохранились. Затем удалите контейнер без удаления тома. Измените переменную окружения, пересоздайте контейнер и проверьте новое значение.
