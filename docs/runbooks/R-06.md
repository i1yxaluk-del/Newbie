# R-06 · Disk space critical (>90%)

**Severity:** P2
**Tier:** all
**Time budget:** 30 мин до < 80%
**Requires:** root / sudo

---

## 1. Триггер

Alert Prometheus: `node_filesystem_avail_bytes / node_filesystem_size_bytes < 0.1`.

---

## 2. Диагностика

```bash
df -h
du -xhd 1 / | sort -h | tail -20
du -xhd 1 /var | sort -h | tail -20
du -xhd 1 /home | sort -h | tail -20
```

---

## 3. Действия

### 3.1. Быстрые wins (часто решает)

- [ ] `apt autoremove --purge` (если Debian/Ubuntu) / `dnf clean all`.
- [ ] Удалить старые kernel (оставить последний + 1).
- [ ] `journalctl --vacuum-time=30d` (ограничить journald).
- [ ] `/var/log` — logrotate статус: `logrotate -d /etc/logrotate.conf`.
  Форсировать: `logrotate -f /etc/logrotate.conf`.
- [ ] Docker: `docker system prune -f --volumes` (если клиент использует Docker).
- [ ] Старые бэкапы на локальном диске: удалить после проверки, что в S3 есть.

### 3.2. Крупные «находки»

- [ ] **Crash dumps** в `/var/crash` — удалить, отключить `apport`.
- [ ] **Tmp** — найти файлы > 1 GB в `/tmp`, `/var/tmp`.
- [ ] **Мусор в /root** (скрипты, загрузки).
- [ ] **Базы данных** — перераспухшие таблицы (VACUUM FULL с осторожностью).

### 3.3. Если нечего удалять

- [ ] Расширить диск в cloud (online, если LVM + ext4/xfs).
  ```
  growpart /dev/sda 1
  resize2fs /dev/sda1   # ext4
  xfs_growfs /           # xfs
  ```
- [ ] Добавить новый диск, перемонтировать `/var`.

---

## 4. Откат

Откат обычно не нужен (удалённые мусорные файлы не возвращают). Если
удалили важное — **не паникуем**: остановить все записи на диск, сделать
снапшот, восстановить через undelete-утилиту.

---

## 5. Проверка

- [ ] `df -h` показывает < 80%.
- [ ] Сервис, которому не хватало места, работает нормально.
- [ ] Не появилось новых ошибок в логах (no-space-left-on-device).

---

## 6. Коммуникация

Обычно клиенту не говорим в моменте — включаем в weekly report.
Если disk был причиной сервис-даунтайма — обязательно.

---

## 7. Post-actions

- [ ] Alert threshold пересмотреть (может, 85% раньше alertить надо).
- [ ] Регулярная tuxedo (weekly cron): автоматическая очистка чего можно.
- [ ] Rate of growth: если > 5% в неделю — клиенту предложить upgrade.
