## Хранилище секретов

Vaultwarden совместим с клиентами Bitwarden и хранит секреты централизованно. Пользовательские учётки, MFA (второй фактор), минимальные права и аварийное восстановление важнее красивой формы входа. Оператор не должен быть единственным владельцем root/domain/cloud recovery клиента. Копия vault на той же VM не поможет при полной потере этой VM.

## Четыре роли в Matrix

Synapse — сервер Matrix: пользователи, комнаты и события. MAS — служба аутентификации, выдающая сессии по OAuth/OIDC. Element/Element X — клиентские приложения. Invite portal — наш прикладной интерфейс приглашений/кабинета. PostgreSQL хранит состояние отдельных сервисов; это не Mongo заявок.

Выбор homeserver через ссылку только подставляет сервер. Браузерная сессия MAS не равна автоматически авторизованному приложению. QR-привязка устройства через MSC4108 — отдельный обмен с подтверждением и ключами. Нельзя рекламировать «вход без повторного пароля работает всегда» без проверки конкретного пути на устройстве.

Токен регистрации, admin client credentials MAS, OIDC credentials портала, личная сессия и Synapse admin token имеют разные полномочия. Удаление аккаунта и повторное использование имени требуют согласованной процедуры в MAS и Synapse, не только деактивации одной записи.

## Другие сервисы

LiveKit/Element Call и JWT-служба обеспечивают отдельный контур звонков; сертификаты и доступность сообщений не доказывают рабочие медиапорты. Prosody/XMPP, invite-сервис XMPP и ntfy имеют собственные данные/порты. Их наличие в `deploy/` не делает их автоматически включёнными в backup основного Compose. Дополнительные контуры требуют своего владельца, цели и проверки; начинающий маркетолог не включает их в тариф по одному найденному README.

## Практика и результат

Нарисовать: создание приглашения → регистрация MAS → браузерная сессия → вход приложения → комната/сообщение. Отдельно обозначить ключи, которые не публикуются, и кого уведомить при ошибке. Владелец подтверждает текущую реализацию; маркетолог пишет только подтверждённый путь пользователя. Материалы: [доступ и коммуникации](../STACK_AND_LEARNING.md).
