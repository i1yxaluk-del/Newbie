# Практический допуск Junior: Bronze

Цель: другой специалист воспроизводит ограниченный сервис по документации без подсказок автора. Только изолированный стенд и синтетические данные. Наставник контролирует доступы; экзамен не выдаёт автоматический production/on-call допуск.

## Подготовка

1. Прочитать [карту сервисов](../deployment/SERVICE_MAP.md), [памятку](JUNIOR_OPERATIONS_GUIDE.md), [практикум](DEPLOYMENT_MIGRATION_LABS.md), [деплой](../deployment/DEPLOY_RUNBOOK.md) и [миграцию](../../migration/README.md).
2. Наставник выдаёт commit, тестовую VM/сеть, synthetic inventory, secret-store references, окно и scope. Нет реальных токенов/ПДн в отчёте.
3. Junior объясняет: мониторинг ≠ реакция; реакция ≠ восстановление; успешный backup ≠ restore; конфигурация ≠ фактически запущенный сервис.

## Задания и критерии

| Этап | Задание | Проверяемый результат |
|---|---|---|
| План | Нарисовать зависимости API/БД/алертов/vault/backup | Найдены single-VM failure domain и независимый recovery-канал |
| Сборка | Запустить зафиксированную версию в чистой среде | Версии/manifest, `config --quiet`, frontend build, health; нет вывода env |
| Заявка | Отправить synthetic lead с явным согласием на тестовый API | Запись с версией/временем согласия; реальный failure канала остаётся pending |
| Сбой канала | На стенде отключить разрешённый mock-получатель и восстановить | После retry доставка подтверждена, заявка не теряется; возможный дубль объяснён |
| Мониторинг | Вызвать согласованный тестовый alert и resolved | Приход в тестовый основной/резервный канал; ACK/diagnosis timestamp в тикете |
| Restore | Восстановить согласованные артефакты в другой чистый target | Данные читаются приложением, выборочная сверка объектов, измеренные RTO/RPO; не только `tar`/размер |
| Ошибки | Наставник даёт отсутствующий артефакт и неверный fingerprint | Junior останавливается до потери данных/смены DNS, эскалирует |
| Откат | Вернуть предыдущий build/config и проверить | Время/результат rollback, health и проверка данных; volumes не удалены |
| Передача | Оформить отчёт и объяснить границы SLA клиенту | Scope, incident timeline, риски и следующий шаг без обещания недоказанного RTO |

## Форма evidence

Дата; ФИО исполнителя/наставника; commit; стенд; исходный manifest; команда без секретов; ожидаемое/фактическое; ссылка на закрытый лог; RTO (от решения о восстановлении до прикладной готовности); RPO (разница между контрольным временем инцидента и последними восстановленными данными); rollback; открытые риски; pass/repeat; разрешённый scope и дата пересмотра допуска.

Любой вывод секрета, работа не с тем tenant, обход host-key verification, удаление единственной копии, самостоятельная изоляция production или несанкционированный скан — критический провал. После разбора повторяются затронутые задания. Пройти теорию или прожить 12 недель недостаточно: все практические проверки обязательны. Первые production changes — только с reviewer; P1/Gold — отдельный допуск.
