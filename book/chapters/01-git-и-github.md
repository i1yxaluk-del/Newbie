# Git и GitHub: как менять проект без страха

Git хранит историю файлов. GitHub хранит копию репозитория на сервере и даёт совместную проверку изменений.

**Репозиторий** — папка проекта вместе с историей. **Коммит** — сохранённая точка этой истории. **Ветка** — отдельная линия работы. **Pull Request**, или запрос на слияние, показывает разницу и позволяет проверить её до попадания в основную ветку `main`.

## Безопасный рабочий цикл

```bash
git status
```

Команда ничего не меняет. Она показывает текущую ветку и изменённые файлы.

```bash
git diff
```

Тоже ничего не меняет. Показывает ещё не сохранённые различия.

```bash
git switch -c fix/readme
```

Создаёт ветку `fix/readme` и переключает рабочую папку на неё. После правки снова выполните `git diff`.

```bash
git add README.md
git commit -m "docs: clarify installation"
git push -u origin fix/readme
```

`git add` выбирает файл для следующего коммита. `git commit` сохраняет выбранное изменение локально. `git push` отправляет ветку на GitHub. Ни одна из этих команд сама не объединяет работу с `main`.

После отправки откройте запрос на слияние. В описании укажите причину, изменённые файлы, способ проверки и риск возврата. Автоматические тесты дополняют чтение разницы, но не заменяют его.

Для отмены уже опубликованного коммита используйте `git revert НОМЕР`. Команда создаёт новый обратный коммит и не переписывает общую историю. `reset --hard` удаляет локальные изменения и в начале обучения не используется.

## Практика

Создайте учебный репозиторий. Измените одну строку в отдельной ветке, просмотрите разницу, сделайте коммит и запрос на слияние. Затем отмените изменение через `revert`. Объясните, почему основная ветка всё время оставалась восстанавливаемой.
