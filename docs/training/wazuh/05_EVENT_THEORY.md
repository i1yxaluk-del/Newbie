# 5. Почему событие становится оповещением

[← Курс](README.md) · [Разобранные ситуации](06_CASES.md)

## Один полный пример

Учебный генератор записывает строку JSON в `training/events.jsonl`. Этот каталог подключён в manager как `/var/ossec/lab` только для чтения: генератор пишет снаружи, manager читает внутри. Это одна и та же информация под разными путями, а не копирование по сети.

```json
{"lab":"msp-junior","synthetic":true,"scenario":"backup_failed","run_id":"учебный-идентификатор"}
```

`localfile` в конфигурации указывает читателю журналов путь и формат `json`. Декодер JSON выделяет поля. Родительское правило `100100` проверяет `lab=msp-junior`; дочернее `100101` использует `if_sid=100100` и проверяет сценарий. Событие удовлетворяет обоим условиям и получает итоговый уровень 6. Просто слово «backup» в любом журнале не должно срабатывать как это правило.

Manager пишет результат в `alerts.json`; Filebeat читает этот файл и передаёт по TLS в indexer. Indexer сохраняет документ, dashboard выполняет запрос по выбранному периоду/полям. Поэтому оповещение может существовать у manager, но ещё не появиться в поиске: отставание и сбой передачи — разные причины.

## Четыре разных времени

1. Когда источник наблюдал событие.
2. Когда manager разобрал его и записал оповещение.
3. Когда оно стало доступно в индексе.
4. Когда человек увидел его в выбранном периоде интерфейса.

Часовой пояс, рассинхронизация часов и задержка передачи меняют картину. `run_id` связывает конкретное упражнение, но не заменяет время. При расследовании сохранить исходное время/зону и отдельно время своих действий.

## Что означает уровень правила

Уровень Wazuh — классификация сигнала правила, а не итоговый ущерб или договорное время реакции. Уровень 8 на учебной проверке доступа не означает подтверждённый взлом. Для приоритета нужны объект, критичность, контекст пользователя, повторяемость и влияние. Ошибка резервной копии критичной БД без других копий может требовать эскалации раньше более высокого, но нерелевантного сигнала.

## Где теряются события

| Звено | Возможная причина | Подтверждение |
|---|---|---|
| Источник | Не создана новая строка, неверный файл | Факт генерации и нужный run_id |
| Чтение | Нет прав, путь не подключён, неверный формат | Права/подключение, сообщения logcollector |
| Правило | Поле называется иначе или условие не совпало | Разбор через `wazuh-logtest` и контрольный пример |
| Передача | Filebeat, TLS, права indexer | Состояние отправки и конкретная ошибка, без публикации токенов |
| Хранение | Недостаток диска/отказ индекса | Здоровье indexer, отказ записи и свободное место |
| Отображение | Период, фильтр, права пользователя | Тот же запрос с известным временем и разрешённой ролью |

Зелёный значок одного звена не заменяет проверку всей цепочки. Отсутствие оповещения — не доказательство отсутствия события.

## Правило и проверка

`wazuh-logtest` проверяет разбор строки и выбор правила, но не запись в файл, передачу Filebeat или появление документа. Сквозная проверка требует пройти весь путь. Для нового правила нужны положительный пример, похожий допустимый пример без срабатывания и случай отсутствующего поля. Начинайте с фикстур, а не с реальной атаки.

Описание правила можно переводить, но имя поля, ID, исходную строку и условия менять ради русского текста нельзя: по ним ищут и связывают документы. Неполный перевод интерфейса не препятствует пониманию, если в курсе раскрыты термины.
