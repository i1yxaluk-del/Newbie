# 7. Устойчивые правила эксплуатации Wazuh

[← Курс](README.md)

## До изменения

Зафиксировать версию компонентов, перечень узлов, источник журналов, права и ожидаемый результат. Manager, indexer и dashboard обновляются по совместимому плану, а не случайно через `latest`. Сохранить конфигурацию/сертификаты и проверенный путь возврата; backup индексов требует отдельного корректного механизма, копирование открытого каталога БД не равно восстановимой копии.

## Меньше данных, больше понятного контекста

- Собирать только согласованные источники; журналы могут содержать ПДн, команды и секреты. Не отправлять raw events в общий чат или внешнюю службу перевода.
- Обозначать клиента/роль узла понятными метками. Совпадающий hostname разных клиентов не даёт права объединять доступ к данным.
- Разделять администратора платформы и читателя событий. «Невидимый пункт меню» не доказывает изоляцию данных — проверить права запросом отдельного пользователя.
- Срок хранения рассчитывать по объёму событий и требованиям, с запасом диска и наблюдением за отказами записи. Удаление индексов по расписанию — осознанная политика, а не случайная уборка.

## Изменение правил без потери наблюдения

Сохранить правило в Git, подобрать свободный ID согласно диапазону своих правил, написать объяснение условий и примеры. Проверить XML/`wazuh-analysisd -t`, затем `wazuh-logtest` с положительным и отрицательным примерами, после — сквозное событие на стенде. Резервная копия, разрешённое окно и точечный перезапуск обязательны для реального изменения. Не менять поставляемые штатные правила прямо внутри образа: обновление их заменит.

Шум уменьшать проверкой источника, исключением обоснованных путей и уточнением условий. Не понижать все уровни и не выключать журналирование, чтобы сделать экран зелёным. Неполученный сигнал опаснее большого счётчика, если вы перестали контролировать важный объект.

## Наблюдать сам Wazuh

Проверять состояние агентов, задержку событий, очереди/ошибки manager, Filebeat, отказ записи indexer, свободное место, срок сертификатов и доступность UI. Доставка сообщения не равна подтверждённому началу работы инженера. Уведомление об отказе всей VM должно уходить с независимой системы.

## Что сдаёт Junior

Не список скриншотов «всё зелёное», а цепочку доказательств: источник и разрешение → контрольное событие → правило/уровень → индекс → отображение → действие ответственного → ограничения вывода. В случае подозрения на инцидент сохранить наблюдения, сообщить старшему и работать по [R-01](../../runbooks/R-01.md); самостоятельное отключение сети/агентов не входит в базовый допуск.
