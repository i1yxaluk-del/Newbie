# 2. Первая практика без изменения серверов

[← Курс](README.md) · [Разбор проекта](03_PROJECT_CASES.md)

## Подготовка

Linux/WSL2, установленный Ansible, обычная учётная запись без sudo. Выполнять из `docs/training/ansible/examples/`. Явно задаём `ANSIBLE_CONFIG=/dev/null`, чтобы настройки production из другого каталога не подхватились. Убедиться, что учебный путь ещё не занят вашими данными; при совпадении остановиться и обсудить с наставником, а не удалять каталог.

```bash
export ANSIBLE_CONFIG=/dev/null
ansible --version
ansible-playbook -i inventory.yml practice.yml --list-hosts
ansible-playbook -i inventory.yml practice.yml --list-tasks
ansible-playbook -i inventory.yml practice.yml --syntax-check
ansible-playbook -i inventory.yml practice.yml --check --diff
```

Разбор команд: `-i` выбирает именно учебный перечень; первый список должен содержать только `localhost`; второй — знакомые задачи. Предварительная проверка сообщает прогноз создания, но файл ещё не появился. Здесь `--diff` разрешён, поскольку содержимое учебное и не содержит секретов.

## Применение и повтор

```bash
ansible-playbook -i inventory.yml practice.yml
ansible-playbook -i inventory.yml practice.yml
```

При первом запуске каталог и файл создаются. При втором, если их никто не менял, ожидается `changed=0`. Откройте только `/tmp/mspshield-ansible-junior/settings.txt`, проверьте текст и права. Если второй запуск снова меняет файл, сравните источник, время/случайные значения в шаблоне и вмешательство другой программы. Не подгоняйте `changed_when: false`, чтобы скрыть проблему.

Теперь измените только учебное сообщение:

```bash
ansible-playbook -i inventory.yml practice.yml -e 'training_message=Второе учебное значение' --check --diff
ansible-playbook -i inventory.yml practice.yml -e 'training_message=Второе учебное значение'
```

`-e` переопределяет стандартное сообщение. Прогноз должен показывать изменение одного файла, а не пакетов или SSH. Возврат к исходному значению выполняется обычным запуском без `-e`: это демонстрация возврата конфигурации, не откат произвольной БД.

## Уборка

```bash
ansible-playbook -i inventory.yml practice.yml -e training_state=absent
```

Удаляется только известный `settings.txt`, затем `rmdir` удаляет **пустой** каталог. Если внутри есть другой файл, `rmdir` завершится ошибкой и сохранит его. Это намеренная защита от удаления чужой работы. После повторной уборки изменений нет.

## Задание с ошибкой

Предложите `-e training_dir=/etc`. Первое утверждение должно остановить выполнение до записи файлов. Объясните, почему ограничение находится до задач, а не после. Затем разберите `--limit`: для настоящего клиента его нужно проверить через `--list-hosts`; правильный тег сам по себе не ограничивает адреса.

Отчёт: версия Ansible, каталог запуска, список узлов, прогноз, результаты двух применений, изменение сообщения, возврат и уборка. Запрещено утверждать, что этот пример проверил доступ по SSH, sudo, установку пакетов или реальный backup: в нём этого нет.
