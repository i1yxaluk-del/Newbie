# 17. Облако и VM с нуля

> **Учебная ситуация.** Чистая VM должна стать предсказуемой базой, а не ручной уникальной машиной.

Предыдущая глава: [глава 16](./16-compose-как-граф-зависимостей.md).

## Модель, которую нужно построить

VM объединяет compute, disk и network interface; public IP обычно реализуется NAT. Security group фильтрует на уровне облака, ufw — на host.

cloud-init выполняет bootstrap один раз. Маркер готовности должен появляться только после фактической проверки Docker/Caddy/Node/unzip.

Service account и ключи ограничиваются необходимыми ролями. Удаление VM не всегда удаляет static IP, snapshots и buckets.

## Термины в рабочем смысле

### IAM

Правила, связывающие identity с разрешёнными actions/resources. Долгоживущий key наследует риск своей роли.

### cloud-init

Bootstrap, выполняемый cloud instance при первом старте. Повторный запуск отдельных частей не всегда эквивалентен новой VM.

### route

Правило выбора interface/next hop для destination. DNS может вернуть правильный IP, но route или провайдерская фильтрация всё равно сделают TCP недоступным.

## Что происходит внутри

Cloud control plane создаёт VM metadata, disk и NIC; guest cloud-init работает уже внутри VM. Ошибка guest package repository не означает ошибку создания VM. Static IP, bucket и IAM key — отдельные resources и требуют отдельного lifecycle/cost review.

## Разобранный пример

```bash
yc compute instance create --name msp-lab \
  --zone ru-central1-a --memory 4 --cores 2 \
  --network-interface subnet-name=default,nat-ip-version=ipv4 \
  --metadata-from-file user-data=deploy/yandex/cloud-init.yaml
```

### Как читать пример

- `yc compute instance create --name msp-lab \` — `yc` вызывает cloud control plane от identity текущего profile; ресурсы и billing создаются вне VM.
- `--zone ru-central1-a --memory 4 --cores 2 \` — Разделите строку на программу/оператор, options и operands; затем по документации установите side effect и exit semantics.
- `--network-interface subnet-name=default,nat-ip-version=ipv4 \` — Разделите строку на программу/оператор, options и operands; затем по документации установите side effect и exit semantics.
- `--metadata-from-file user-data=deploy/yandex/cloud-init.yaml` — Разделите строку на программу/оператор, options и operands; затем по документации установите side effect и exit semantics.

## Если результат не совпал с ожиданием

| Наблюдение | Что это означает | Следующая проверка |
|---|---|---|
| apt завис на IPv6 | Это сужает область поиска, но не доказывает единственную причину | использовать диагностированный ForceIPv4, а не бесконечный retry. |
| IP сменился после stop/start | Это сужает область поиска, но не доказывает единственную причину | нужен reserved static IP. |

## Самостоятельная работа

Решите изменённый вариант исходной ситуации: **Чистая VM должна стать предсказуемой базой, а не ручной уникальной машиной.** Измените один существенный параметр — host, port, credential, dataset, пакет или ограничение клиента — и сначала письменно предскажите результат. Затем выполните проверку на безопасном стенде. В отчёте оставьте исходное предположение, фактическое наблюдение, причину расхождения и способ восстановления.
