# Сайт, серверная часть, MongoDB и очередь

Сайт состоит из интерфейса в браузере и серверной части. Интерфейс показывает форму. Серверная часть принимает запрос, проверяет данные и решает, что сохранить.

FastAPI — библиотека Python для HTTP-запросов. Uvicorn принимает сетевое соединение и передаёт запрос FastAPI. Pydantic проверяет форму данных. Код `422` обычно означает ошибку структуры запроса, а `500` — необработанную ошибку программы.

MongoDB хранит документы. Документ похож на объект с полями. Коллекция — группа документов. Запись заявки должна завершиться до ответа об успехе.

Интеграции с Kaiten и почтой могут временно не работать. Поэтому заявка сначала сохраняется, а отдельная запись в **очереди исходящих действий** фиксирует, что ещё нужно отправить. Обработчик повторяет попытки. Это называется outbox; русское объяснение важнее названия: не терять внешнее действие после сохранения заявки.

```text
Форма → проверка согласия → запись заявки
                         └→ запись задания отправки
                              → Kaiten
                              → почта
```

SmartCaptcha отсеивает часть автоматических отправок. Нужно заранее решить, что происходит при недоступности проверки. Для рабочей формы согласие на обработку данных должно быть явным; отсутствие галочки не исправляется автоматически.

## Диагностика

Начните с ответа браузера и времени запроса. Затем смотрите журнал Caddy, серверной части и состояние MongoDB. Не делайте вывод только по одному `200`: проверьте, появилась ли запись и обработалась ли очередь.

## Практика

Отправьте корректную тестовую заявку. Найдите её в базе и проследите отправку. Затем временно укажите неверный адрес Kaiten. Убедитесь, что заявка сохранилась, задача осталась в очереди и после восстановления связи отправилась один раз.
