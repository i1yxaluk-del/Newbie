# Кураторская видеотека MSPShield Academy

Эта страница заменяет автоматически созданные ссылки на поиск YouTube. Здесь нет обещания, что ролик «закрывает тему»: у каждого материала указаны польза, границы и обязательная практика.

## Правило отбора

Материал включается, если он показывает механизм или полный рабочий процесс, имеет понятную структуру и позволяет выполнить проверяемое действие. Ролики, состоящие из мотивации, обзора кнопок или продажи курса, не используются как основной источник. Официальная документация и репозиторий всегда важнее видео.

## Базовый технический маршрут

### Сеть

**[Введение в сетевые технологии: OSI, TCP/IP, устройства и протоколы](https://www.youtube.com/watch?v=I-wye8War5g)**

Почему включено: строит связную модель уровней сети вместо списка команд. После просмотра нарисуйте путь `браузер → DNS → TCP → TLS → Caddy → backend` и для каждого уровня укажите отдельную проверку. Не переносите лабораторные адреса и firewall-правила в production.

### systemd и журналы

**[Системный журнал Linux: journalctl](https://www.youtube.com/watch?v=19Q0euPOQoY)**

Почему включено: показывает journald и фильтры журнала, необходимые для deploy и incident response. Практика: найти сообщения одного unit за текущую загрузку, ограничить интервал времени и сохранить evidence без секретов.

### Git и GitHub

**[Git. Большой практический выпуск](https://www.youtube.com/watch?v=SEvR78OhGtw)**

Почему включено: длинный практический разбор локального Git, истории и веток; подходит как база перед GitHub. После просмотра воспроизведите commit → branch → merge → recovery в тестовом репозитории.

**[Git: конфликты, cherry-pick, revert и reset](https://www.youtube.com/watch?v=F7FnnfnB9YY)**

Почему включено: разбирает различия между способами отмены и реальные конфликты. Для общего репозитория MSPShield предпочтителен новый `revert`, а не переписывание уже опубликованной истории. Выполните лабораторную из [`guides/GITHUB_OWNER_WORKFLOW.md`](guides/GITHUB_OWNER_WORKFLOW.md).

### Docker

**[Что такое Docker — открытая лекция Слёрма](https://www.youtube.com/watch?v=TJg7QpqCH70)**

Почему включено: объясняет происхождение контейнеризации и базовую модель, а не только команды. После просмотра объясните, почему container не VM и почему удаление container не должно удалять volume.

**[Docker: полный курс для начинающих](https://www.youtube.com/watch?v=_uZQtRyF6Eg)**

Используйте выборочно: images, Dockerfile, volumes, networks и Compose. Не копируйте демонстрационные публикации портов и секретов. Сравнивайте каждую команду с текущими файлами `deploy/yandex/`.

### FastAPI

**[FastAPI: полный курс за 3 часа](https://www.youtube.com/watch?v=8Zrt6VOBI_Y)**

Почему включено: последовательно проходит request path, schemas и endpoints. В ролике есть предложение платных материалов — его можно пропустить; техническую часть проверяйте по официальной документации FastAPI. Практика: проследить один запрос до функции и Mongo/outbox, затем добавить отрицательный тест валидации.

### Prometheus и alerting

**[Слёрм Prom: вводная лекция по Prometheus](https://www.youtube.com/watch?v=WJ3FFrOT_ko)**

Почему включено: материал ведёт инженер курса Prometheus; годится для построения mental model pull-сбора и временных рядов. После просмотра найдите target, выполните один PromQL-запрос и объясните, почему наличие метрики не доказывает здоровье пользовательского пути.

**[Introduction to the Prometheus monitoring system — PromLabs](https://www.youtube.com/watch?v=STVMGrYIlfg)** *(английский)*

Короткое объяснение архитектуры автором обучающих материалов Prometheus. Используйте, если английский не мешает пониманию. Затем сопоставьте scrape, labels, rule и Alertmanager с Compose MSPShield.

### Backup и restore

**[Backups Done Right: руководство по restic](https://www.youtube.com/watch?v=Br-h-fjwzYM)** *(английский)*

Почему включено: показывает repository, snapshot, backup и restore как единый цикл. Просмотр не засчитывается без clean-room restore и измерения RTO/RPO. Политику retention и credentials берите из runbook проекта.

## Облако и рабочие инструменты

### Yandex Cloud

**[Как начать работу в Yandex Cloud: пошаговая инструкция для новичков](https://www.youtube.com/watch?v=u9PI_VncAd4)** — официальный канал Yandex Cloud.

Полезные части: организация ресурсов, создание VM и базовые операции. Интерфейс консоли может измениться; source of truth — актуальная документация и [`guides/YANDEX_CLOUD_OWNER.md`](guides/YANDEX_CLOUD_OWNER.md). После просмотра создайте учебную VM без production-секретов, проверьте security groups и удалите платные ресурсы.

**[Из чего состоит IAM](https://www.youtube.com/watch?v=JCu5WD1o9Is)** — инженерный доклад Yandex Cloud.

Используйте для понимания аутентификации, ролей и области действия прав. Практика: объяснить, почему постоянный ключ владельца в `.env` опаснее service account с минимальной ролью.

### Kaiten и Kanban

**[Где отображаются задачи в Kaiten: работа с карточками](https://www.youtube.com/watch?v=mXpJ9frcFY4)** — официальный канал Kaiten.

Это ввод в механику карточек, не модель MSP-процесса. После просмотра настройте тестовую карточку с owner, deadline, service class и Definition of Done.

**[Автоматизации в Kaiten](https://www.youtube.com/watch?v=QfYok88UGbA)** — официальный канал Kaiten.

Сначала воспроизведите правило в тестовом пространстве. Автоматизация не должна закрывать incident или change без человеческой проверки evidence.

**[О WIP-лимитах и классах обслуживания](https://www.youtube.com/watch?v=LdguvbxPRR8)**

Почему включено: объясняет механизм ограничения незавершённой работы и классы обслуживания, а не обзор интерфейса. Для команды из двух человек лимит должен отражать реальную capacity, а не желаемое число клиентов.

## Экономика и продажи

### Unit economics

**[Unit-экономика для продактов](https://www.youtube.com/watch?v=5DGeIBjYQEI)**

Почему включено: вводит модель unit economics и связь решения с прибыльностью. Для MSP замените абстрактный unit на «клиент-месяц» и включите стоимость собственного времени, налог, банк, переменные расходы и incident reserve. Не переносите SaaS-бенчмарки без проверки.

### B2B discovery

**[The Ultimate Discovery Guide for B2B Sales](https://www.youtube.com/watch?v=UXD-aJLcxLA)** *(английский)*

Почему включено: содержит полный framework подготовки и discovery, баланс вопросов и обучения клиента, работу с участниками решения. Есть внешние ссылки автора, но для прохождения они не нужны. Практика: провести role-play по сценарию MSPShield и получить явный next step, не обещая SLA до capacity check.

### Воронка

**[Воронки продаж: от первого касания до покупки](https://www.youtube.com/watch?v=WICxdq67Qko)**

Берите только механику стадий, конверсии и экономики; авторские предложения услуг пропускайте. Практика: рассчитать stage conversion на тестовых данных и доказать, почему количество лидов без определения стадий не является управленческой метрикой.

## Темы без рекомендованного видео

Для MAX userbot, Stalwart/Postbox, точного migration runbook и юридической обработки ПДн нет выбранного русскоязычного ролика, которому можно доверить обучение Owner. Здесь намеренно используются главы книги, исходный код, официальные документы и лабораторные работы. Случайная ссылка была бы хуже честного отсутствия видео.

## Как пересматривать каталог

Раз в квартал проверяйте доступность ссылки, автора, дату, соответствие текущим версиям и отсутствие подмены содержания. Удаляйте материал, если практическая часть больше не воспроизводится или ролик превратился в рекламную воронку.
