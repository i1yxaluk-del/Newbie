## Три уровня результата

Копирование файла подтверждает, что байты были сохранены. Чтение из копии подтверждает доступ к сохранённым данным. Восстановленное приложение с проверенными данными подтверждает пригодность сценария восстановления. Эти уровни нельзя смешивать в отчёте.

RPO — допустимая потеря последних данных во времени; RTO — допустимое время возврата согласованной функции. На практике измеряются фактическая восстановленная точка и время до прикладной готовности. Скрипт `dr_drill.sh` теперь выдаёт `restore_only`: его время файловой операции не является RTO системы.

## Что копирует проект

Основной migration kit включает логический dump Mongo, Vaultwarden, оба Stalwart-тома и MAX session. Логический dump работающей standalone Mongo может не дать согласованную межколлекционную точку при продолжающихся записях. Для миграции требуется согласование остановки writers или иной проверенной стратегии.

MAS/Synapse PostgreSQL, media/keys Matrix и другие сервисы имеют отдельные требования. Архив `/opt` полезен для файлов, но не доказывает согласованный backup открытой БД. Restic шифрует репозиторий; доступ к S3 и пароль расшифрования — разные обязательные зависимости.

## Перенос VM

Сначала перечень данных и проверенные копии → новая VM/секреты → восстановление → прикладные проверки → основной/резервный alert → внешний HTTPS → решение DNS → наблюдение и срок возврата. Старые cloud credentials не копируются по привычке. Snapshot полезен, но не заменяет восстановление на чистой среде.

## Практика и результат

Выбрать один объект договора и составить полный рецепт: источник, формат, ключ, target, зависимости, допустимая потеря, приёмка пользователем. Объяснить, что произойдёт при утрате ключа и при повреждённом архиве. Удаление истории через prune не является универсальным лечением corruption.
