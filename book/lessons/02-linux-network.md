## Почему диагностика идёт по слоям

Сайт может не открываться из-за имени, маршрута, порта, сертификата, приложения или БД. Перезапуск всего сразу уничтожает исходные признаки и затрагивает другие службы. Сначала определить, на каком слое отличается ожидаемое поведение.

IP — адрес узла, порт — вход конкретной службы. TCP подтверждает транспортное соединение. TLS шифрует его и проверяет удостоверение сервера. HTTP переносит запрос приложения. `ping` использует другой механизм и не подтверждает работу HTTPS. VPN создаёт защищённый маршрут, но не заменяет права пользователя в приложении.

## Процессы, файлы и права

Linux запускает процессы от пользователей. Права файла определяют, кто может читать настройки/секреты и изменять код. В systemd `User` задаёт учётную запись службы, `ExecStart` — запускаемую программу, `EnvironmentFile` — файл переменных. `After` задаёт порядок, а не проверку здоровья зависимости.

В Docker программа имеет собственное окружение и часть файловой системы. Путь внутри контейнера может соответствовать подключённому каталогу host; это нужно выяснить до удаления или смены прав. Не используйте `chmod 777`, чтобы убрать непонятный отказ доступа.

## Команды только чтения

`hostname` показывает, на какой машине вы находитесь; `uptime` — время работы и нагрузку, `df -h` — занятое место разделов, `free -m` — память. `systemctl status caddy` показывает состояние host-службы, `docker ps` — контейнеров. Журнал может содержать ПДн/секреты: перед передачей очистить значения, а не публиковать целиком.

Сверка SSH fingerprint защищает от входа на другой сервер. Изменение ключа — повод проверить через console/provider, а не автоматически отключить контроль. Персональный доступ позволяет связать действие с человеком; общий пароль мешает расследованию и отзыву прав.

## Практика и результат

На учебной машине сопоставьте: имя процесса → пользователь → порт → конфигурация → каталог данных → проверка приложения. Затем разберите timeout, connection refused и HTTP 502: какие разные проверки нужны? Маркетологу достаточно понимать, почему нельзя обещать «исправить интернет» по сообщению браузера.
